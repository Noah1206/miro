# 긴 맥락 기준 (2026-11-10, 크랙 대비)

크랙(뤼튼)이 공개한 구조: 캐릭터 프롬프트 최대 3000자 + 최근 대화 + 길어지면 이전 대화를 요약해 함께 넣는 "장기 기억(요약 메모리)" + 사용자가 300자 안팎으로 적는 "유저노트". 요약 메모리는 사용자가 보충·삭제할 수 있고, 2025년에 최대 크기를 33% 늘렸다. 크랙 스스로 "긴 맥락의 가운데는 모델이 잘 못 쓴다"고 안내한다.
출처: https://help.crack.wrtn.ai/character/prompt , 크랙 공지(요약 메모리 개선), 이용자 커뮤니티의 유저노트 설명.

## 미로 기준 (이 수치 아래로 내리지 않는다)

| 층 | 미로 | 크랙(공개 기준) |
|---|---|---|
| 캐릭터 설정 | 제한 없음(맥락 예산 안) | 3000자 |
| 최근 대화 원문 | 30개 메시지(15턴), ECHO 이상은 최대 60개 | 비공개 |
| 요약(지금 이야기) | 10턴마다 갱신, 1500자 | 비공개(33% 확대) |
| 지난 이야기 | 요약이 바뀔 때마다 보관, 8편 넘으면 1500자로 합침, 입력과 맞는 1~2편 실음 | 없음(요약 하나) |
| 사실 기억 | 턴마다 16개(고정 5개 우선, 약속·갈등·호칭 자리 따로), 방마다 120개 | 비공개 |
| 유저노트 | 1000자, 매 턴 최근 대화 **뒤**에 | 300자(확장 시 늘어남) |
| 기억 편집 | 고치기·고정·지우기·직접 적기·지난 이야기 합치기 | 보충·삭제 |
| 맥락 예산 | 46,000자(글자 단위 — 공급자 입력 상한 64,000과 같은 셈) | 비공개 |

## 설계 이유

- 요약 주기(10턴)가 원문 창(15턴)보다 짧다 → 창에서 빠지는 대화는 언제나 이미 요약에 들어 있다. 12턴 주기·6턴 창일 때는 7~12턴 전 일이 사실 기억으로만 남았다.
- 유저노트는 맥락 맨 끝(사용자 입력 바로 앞)에 둔다 — 가운데에 두면 잊힌다(크랙이 인정한 한계).
- 지시문의 고정 부분(캐릭터·규칙)은 앞, 이번 턴 지시(분량 장면 지시·턴 수)는 맨 끝 → Claude 는 앞부분을 캐시한다(`cacheSystemPrefix`).
- 입력 상한은 바이트가 아니라 글자로 센다. 한국어 1글자 = 3바이트지만 토큰은 약 1개 이하라, 바이트 셈이 실제 맥락을 3분의 1로 막고 있었다.

## 코드 위치

- 예산·창: `packages/config/src/index.ts` `context`
- 조립: `packages/engine/src/context.ts` `buildContext`·`buildPrompt`(유저노트)
- 요약 주기·길이: `packages/engine/src/task-router.ts`
- 지난 이야기 보관: `apps/web/lib/simulation/commit.ts`(되돌릴 수 있는 턴 포함), 합치기 `apps/web/lib/ai/memory-compact.ts`
- 유저노트: `roleplay_sessions.user_note`, API `app/api/memory-graph/[sessionId]`(action `note`), 화면 기억 노트 맨 위
- 입력 상한: `packages/providers/src/ai/turn-meter.ts` `generationInputCeiling`

## 남은 것

- 실측: 100턴·300턴 대화에서 이름·약속·관계를 기억하는지 시나리오 측정(사용자 승인 후, 실측 예산 안에서).
- 요약 작업이 실패하면 그 10턴은 다음 주기까지 요약에 안 들어간다(재시도 없음).
