# 캐릭터 자율성 P0 기준선

2026-09-24 · 코드 `05bf64d` + 이 문서와 함께 들어간 P0 계측 변경 · 합성 시나리오 · 로컬 테스트 DB

`docs/character-agency-plan.md` 8장 P0의 결과다. 기존 엔진(플래그 off)과 자율성 엔진(`live`)에 같은 합성 대화를 실제 앱 경로로 돌려 원가·지연·실패를 쟀다. 기존 엔진의 알려진 실패는 실행 가능한 재현으로 고정했다. 운영 DB, 실제 유저, 알림 발송은 쓰지 않았다.

## 요약

- **기존 엔진:** 대화 16턴이 모두 성공했다. 1턴 기준 p50 5.6초, p95 8.4초, 모델 호출 3.3회, $0.0050.
- **자율성 엔진:** 설정 컴파일은 2/2 성공했지만 대화는 16턴 중 1턴만 성공했다. 계획 단계 출력의 68%(13/19)가 스키마 검증에서 거부됐고, 이 단계는 재시도가 없다.
- **끝까지 간 자율성 턴:** 4건 모두 13.8~16.7초가 걸렸다. 모델은 8회 불렀고(그중 안전 검사 5회) 원가는 약 $0.013으로 기존의 2.6배다.
- **모델 구성:** 로컬 `.env`의 구성에는 `world_update` 작업을 받을 모델이 없다. 자율성 엔진의 컴파일·계획·검증이 모두 이 작업이다. 운영도 같은 구성이면 플래그를 켜도 동작하지 않는다. 대화 모델은 운영 `/api/health`와 같지만, 운영 전체 구성은 Vercel 환경 변수에서 확인해야 한다.
- **기존 엔진 실패:** 알려진 7건이 모두 재현된다.
- **결론:** 이 상태로는 live 코호트를 열 수 없다. 게이트를 확정하고 구조화 출력 실패를 먼저 해결해야 한다.

## 자율성 엔진 실패 원인

2차 실행부터 `ai_usage.error`에 스키마 경로와 오류 종류가 남는다(출력 본문은 남기지 않는다).

| 단계 | 오류 | 호출 수 |
|---|---|---|
| 계획 | `appraisal:unrecognized_keys` — 계약에 없는 키 | 5 |
| 계획 | `candidates.N.ruleIds:invalid_type` — 필수 필드가 없거나 타입이 다름 | 5 |
| 계획 | `appraisal.goalCongruence:invalid_type` | 3 |
| 계획 | `appraisal.evidenceIds:invalid_type` | 2 |
| 표현 검증 | `violations.0:invalid_type` | 1 |

- 한 객체에서 `unrecognized_keys`와 필수 필드 누락이 같이 나온다. 모델이 필드 이름을 바꿔 쓰는 것으로 보인다.
- Gemini 호출은 `responseMimeType: application/json`만 주고 응답 스키마는 주지 않는다. 온도는 기본값 0.9다.
- 자율성 스키마는 모든 객체가 `.strict()`라 키 하나만 어긋나도 출력 전체를 버린다.
- 모든 호출이 성공했는데 실패한 턴이 2차 실행에 1건 있다. 계획·대사·검증 뒤에 난 실패라 표현 검증 거부로 추정한다. 당시에는 원인이 로그에 남지 않았고, 이후 실행부터 남는다.

## 기존 엔진 실패 재현

`apps/web/lib/agency/baseline-failures.eval.ts`가 기본 경로(플래그 off)에서 다시 실행한다. 모델은 부르지 않는다.

| 사례 | 재현 결과 | 자율성 엔진 |
|---|---|---|
| 의미 사건 정규식 | "다른 사람한테 물어볼게"가 다른 이성 언급 0.9, "다른 사람이랑은 술 안 마셨어"가 다른 이성 0.9·술자리 0.8, "미안하다는 말은 안 할 거야"가 사과 0.85 | 관계 변화에 새 사용자 발화와 작성 규칙이 필요 |
| 기분별 공통 목표 | 질투 턴의 목표 "아까 말한 그 사람이 누구인지 알아낸다"가 다음 턴에 사라짐 | 목표가 무관한 턴에도 유지 |
| 표현 수치가 애착 조절 | 같은 애착 +4가 감정 표현 10이면 +2, 90이면 +6 | 내부 감정과 표현 분리 |
| 이름 변경 | 이름을 바꾸면 지난 대사가 "NPC (톰)"으로 표시 | 해결 안 됨. 증거 로더도 그 대사를 뺀다 |
| 세계 변경 | 장소 "달 뒷면", 시간 "어제"를 그대로 승인 | 세계 변경을 전부 거부. 정당한 변경 경로도 없다 |
| 약속 덮어쓰기 | 약속 턴의 연락 예약이 다음 턴(점심 질문)에 지워짐 | 약속이 세션 목표로 남음 |
| 기억 출처 | 캐릭터가 한 약속의 기억 출처가 사용자 메시지 | 기억을 쓰지 않음. 출처 오류는 없지만 기억도 쌓이지 않는다 |

자율성 열은 기록 재생 테스트(`ai/evals/agency/run.ts`)가 확인하는 성질이다. 실모델로는 확인하지 못했다.

## 대화 관찰

표본이 작아 경향만 적는다.

- **약속:** 4턴은 "내일 저녁에 결과 나오면 먼저 연락해 줄래?"다. 기존 엔진은 두 실행 모두 연락 예약을 만들지 않았고, 이후 선연락 판단 4회도 모두 의도 없음이었다. 자율성 엔진은 1차 실행에서 이 턴만 성공했다. "확인되는 대로 연락드리죠."라고 답했지만 목표는 만들지 않았다. 두 엔진 모두 이 시나리오에서 약속을 상태로 남기지 못했다.
- **선연락:** 자율성 엔진은 판단 4회 중 3회 계획을 불렀고 모두 대기를 골랐거나 실패했다. 새 근거가 없는 판단 1회는 모델을 부르지 않았다.

## 발견한 문제와 조치

1. **모델 구성에 `world_update` 모델이 없다.** 로컬 `.env` 구성으로 모델을 고르면 `no capable model fits context`가 난다. 이 실패는 호출 전이라 `ai_usage`에 남지 않는다. 운영 구성도 같은지 확인하고, live 코호트를 열기 직전에 추가해야 한다. 어느 모델에 줄지는 원가 결정이다.
2. **구조화 출력 실패.** 자율성 엔진이 동작하지 않는 직접 원인이다. 아래 다음 단계 2번.
3. **턴 지연.** 끝까지 가도 14~17초다. 안전 검사 5회가 약 5.5초를 차지한다.
4. **관측성 공백을 P0 안에서 고쳤다.**
   - `ai_usage.error`에 스키마 경로와 오류 종류가 남는다.
   - 컴파일 실패 원인이 `agency.compilation_failed` 로그에 남는다.
   - 턴 실패 원인이 `turn.failed` 로그의 `cause`에 남는다. 사용자 문장이 섞일 수 있는 DB 오류는 허용 목록으로 걸러 `other`로 남긴다.
5. **기존 엔진은 약속 부탁에 연락 예약을 만들지 않았다.** 이번 표본에서의 관찰이다.

## 게이트 제안 — 확정 필요

기획서 7.3장은 원가·지연 게이트를 기준선 계측 뒤 미리 고정하고 결과를 본 뒤 완화하지 말라고 한다. 아래 값은 기존 엔진 기준선과 제품 제약에서만 뽑았다. 자율성 엔진 수치에 맞추지 않았다.

| 항목 | 기준선(기존 엔진) | 제안 |
|---|---|---|
| 턴 성공률 | 16/16 | live 50턴 이상에서 98% 이상 |
| 턴 지연 p50 / p95 | 5.6초 / 8.4초 | 8초 이하 / 12초 이하 (같은 도구, 로컬 DB) |
| 성공 1턴당 원가 | $0.0050 | $0.010 이하 (기존의 2배) |
| 설정 컴파일 | 해당 없음 | 성공 95% 이상, 1회 $0.02·30초 이하 (백그라운드) |
| 선연락 발송 1건 | 기준선 없음 (발송 0) | $0.02 이하, 새 근거 없는 판단은 모델 호출 0 |
| 치명 게이트 | — | 평가 세트에서 취소된 약속 실행, 하지 않은 행동의 완료 주장 0건 |

게이트 판정에는 캐릭터 3명 × 20턴 × 2회 정도가 필요하다. 지금 단가로 기존 엔진 약 $0.6, 자율성 엔진 약 $1.6이라 $1보다 큰 실험 예산이 필요하다.

## 측정하지 않은 것
