# 인트로 대화

새 채팅용 인트로는 만들기/수정의 인트로 탭에서 편집한다. 프로필 고급 설정 아래 `상황 예시 추가`는 상세페이지 소개용 샘플을 별도로 편집한다. 캐릭터 대사와 내레이터만 허용한다. 최대 20개 메시지, 메시지당 500자, 합계 2,000자를 클라이언트와 서버에서 제한한다. 상세 미리보기와 새 대화에는 같은 인트로를 표시한다.

기존 `characters.sample_dialogue` JSON 배열의 각 인트로 항목에 `purpose: "intro"`를 저장한다. 스키마 타입에 선택적 구분값을 추가했으며 SQL 구조 변경은 없다. 구분값 없는 기존 소개 샘플은 보존한다. `introDialogue`와 `sampleDialogue` 함수로 소비 경로를 분리한다. 기존 소개 샘플을 인트로로 자동 변환하지 않는다.

새 세션 생성 트랜잭션에서 메시지를 순서대로 복사한다. 등록 직후 세션, 초안 등록 세션, 일반 채팅 시작 세 경로 모두 적용한다. 인트로의 `turn_index`는 -N..-1이며 실제 사용자 턴과 과금 횟수를 올리지 않는다. 명시적 시스템 opening 옵션은 기존 우선순위와 turn 0을 유지한다. AI는 복사된 인트로를 실제 최근 대화로 읽으며 말투 샘플로 중복 주입하지 않는다.

기존 세션 재진입은 메시지를 추가하지 않는다. 일반 시작 경로는 사용자/캐릭터별 transaction advisory lock 후 세션을 재확인하여 동시 클릭으로 중복 세션과 인트로가 생기지 않게 한다. 캐릭터의 인트로를 수정해도 진행 중인 세션 기록은 변경하지 않는다.

배포할 때 생성/수정, 상세 필터, 세션 시작, 스냅샷 변경을 함께 배포한다. 구버전 앱은 purpose 구분을 모르므로 신규 인트로 데이터를 만든 뒤 구버전으로 되돌리면 소개 샘플로 보이거나 편집 시 구분값이 사라질 수 있다. 롤백은 이 호환성을 고려한다.

검증: 로컬 miro_test에서 저장 파싱, 실제 DB 세션/인트로 메시지, 동시 시작 3회, 재진입, 소유권, 레거시 보존, AI 스냅샷 검증. 운영 DB 테스트 및 배포는 실행하지 않는다.


## 2026-10-15 도입부 전수 편집

현재 공개 중인 12명·36개 시작 장면을 유저의 현재 위치와 당면한 일에서 시작하도록 편집했다. 별도로 보관 중인 2명·2개 도입부도 같은 기준으로 정리했다. 모든 장면은 서술–캐릭터 대사–캐릭터 행동의 서술–응답을 기다리는 캐릭터 대사 4개 항목이며, 마지막 대사가 서술로 표시되는 문제를 없앴다. 감정·결정·새 행동을 유저에게 대신 부여하지 않는다.

편집본은 `apps/web/lib/editorial/official-copy.json`에 있다. 캐릭터 ID와 원본 텍스트 해시가 맞는 경우만 반영해 후속 제작자 수정을 보존한다. 기본 시작 상황은 홈 카드·상세·페르소나 설정·AI 맥락에 같은 편집본을 사용한다. 다른 시작 장면은 수정된 첫 서술을 시작 상황으로 사용하고, 장면 사진·시간·장소·선택 키를 보존한다. 새 세션만 수정본 인트로를 복사하며 이미 진행한 대화 기록은 다시 쓰지 않는다.
