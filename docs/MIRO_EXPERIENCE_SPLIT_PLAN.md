# 홈 / 미로 경험 분리 기획·개발 계획

2026-09-16. 기준 커밋 e3aa78c. 이 문서는 제안 계획이며 앱 구현 완료를 뜻하지 않는다.

## 구현 상태 — 2026-09-16

7장의 순서 1~5 를 구현했다. 순서 6(실제 Reality 검증 후 활성화)은 하지 않았다 —
운영의 `realityMessage`·`inlineReality`·사진·통화·Live 차단은 그대로이고, 결제도 바꾸지 않았다.

- `characters.experience_type` (`chat`|`reality`, CHECK, 기본 `chat`). 기존 캐릭터는 전부 chat 으로 남았다.
- 서버 경계: scheduler 후보 JOIN, `evaluateSession` 최종 검사(+chat 세션에 남은 의도 정리), 턴 직후
  inline·`pendingRealityIntent` 저장 차단, push-outbox 재시도 시 재검증, 사진·통화·Live 직접 요청 거절.
- 홈·검색·비슷한 캐릭터·이어서 대화하기는 chat 만, `/miro` 는 reality 만. `/discover` 는 `q` 를 들고
  `/home/search` 로 간다. `/archive` 는 둘 다 보존한다.
- UGC 는 파서가 필드를 화이트리스트해 유형을 넣을 수 없다. 지정은 운영 콘솔 `/characters`
  (`characters.manage`, superadmin) 에서만 하고, reality→chat 은 같은 트랜잭션에서 그 캐릭터 세션의
  대기 의도와 대기 Push 를 정리하며 감사 로그에 남는다.
- **미로에 넣을 캐릭터는 아직 지정하지 않았다.** `/miro` 는 비어 있다. 8장의 결정은 그대로 남는다.

## 1. 확정된 제품 방향

- 홈: 일반 캐릭터챗 전용 캐릭터. 유저가 들어와서 대화하며 자동 Reality 연락은 발생하지 않는다.
- 미로: Reality 전용 캐릭터. 대화·관계·시간을 근거로 연락과 교감이 이어진다.
- 기존 발견(사용자가 부르는 탐색) 탭을 미로로 교체한다.
- 제목은 ‘미로’. 기능 배지, 긴 소개, 설명용 슬로건은 추가하지 않는다.
- 단순히 같은 캐릭터를 두 목록으로 필터링하는 기획이 아니다. 캐릭터 소속과 서버 실행 자격을 함께 분리한다.

## 3. 화면과 유저 흐름

### 홈

공개된 두 유형(일반·미로)을 모두 노출한다(2026-09-23 변경, b17df11 — 처음 계획은 일반만). 검색(/home/search)은 일반 캐릭터, /miro 는 미로 캐릭터만 다룬다. 카드 → 기존 상세페이지 → 대화 흐름은 유지한다. 대화한 캐릭터라도 홈 카드에서는 상세로 진입하는 기존 사용자 결정을 유지한다.
일반 대화에도 말투·기억·관계 연속성은 유지한다. 일반 채팅을 일회성 챗봇으로 축소하지 않는다. 자동 선톡·앱 밖 연락·Reality 사진/통화는 발생하지 않는다.

### 미로

/miro 페이지에 Reality 전용 캐릭터만 표시한다. 기존 카드와 앱 디자인을 재사용한다. 처음에는 캐릭터 이미지·이름·짧은 소개를 중심으로 구성한다.
연결한 캐릭터가 있으면 위에 배치할 수 있으나, 초기 필수 범위는 목록 → 상세 → 대화 진입까지다. 가짜 온라인 상태·미발생 연락·미지원 기능은 표시하지 않는다.
설명 문구 대신 실제 대화 이후의 연락으로 차이를 체험한다. OS 알림 권한 요청과 유료 소비 조건처럼 필요한 동의는 생략하지 않는다.

### 대화

/archive는 두 유형의 기존 대화를 모두 보존한다. 1차에는 별도 필터를 추가하지 않는다. 각 대화의 캐릭터 유형에 맞는 기능만 실행한다.

**응답 형식 (2026-09-24 결정).** 미로 캐릭터는 캐릭터챗에 Reality가 더해진 것이다. 캐릭터챗은 두 유형 모두 만나서 나누는 장면으로 같은 형식을 쓴다.
- 캐릭터챗: 입력이 짧아도 매 응답에 캐릭터의 행동·장면 분위기 서술, 말하지 않은 속마음(`thought` 블록), 대사를 담는다. 속마음은 화면에서 왼쪽 선이 있는 흐린 기울임체로 구분한다. 메시지 본문 텍스트·기억·분석·근거에는 들어가지 않고, 다음 턴에는 "소리 내어 말하지 않음"으로 캐릭터에게만 보인다.
- Reality(먼저 오는 메시지·사진·통화): 실제 메신저·통화처럼 서술과 속마음이 없다. 마음은 답장 속도, 말투, 먼저 연락하거나 기다리는 선택으로 드러낸다. 통화에서는 `thought` 블록을 버린다.
- 미로 캐릭터의 캐릭터챗은 직접 만나 같은 공간에 있는 장면으로 쓴다. 첫 장면이 연락으로 시작했더라도 채팅을 메신저 화면(읽음 표시, 입력 중 표시)으로 서술하지 않는다. 일반 캐릭터는 작성자 설정을 따른다.
- 실측(2026-09-24, gemini-3.8-flash): 기존 엔진 2명 16턴과 규칙 뒤 재측정 8턴, 모두 24턴이 상황·속마음·대사를 갖췄다. 직접 만남 규칙 전에는 첫 장면이 문자인 미로 캐릭터(유진)가 메신저 화면으로 서술했고, 규칙 뒤 8/8 만나는 장면이 됐다. 자율성 엔진은 예산으로 멈춘 3턴 중 성공한 2턴이 형식을 갖췄다. 원본은 `ai/evals/agency/reports/format-*-2026-09-24.json`.

### 기존 주소

/discover는 /home/search로 리다이렉트해 일반 캐릭터 검색 용도를 보존한다. 기존 q 검색어도 전달한다. 이를 /miro로 보내면 일반 검색 링크의 의미가 바뀐다.

## 4. 데이터·권한 설계 제안

- 캐릭터에 experienceType = chat | reality 추가. DB 제약으로 허용값 제한, 기본값 chat.
- 캐릭터 하나는 한 유형에만 소속한다. 동일 캐릭터를 두 경험으로 동시에 제공하는 복제 기능은 1차 범위에서 제외.
- 세션은 기존 characterId 관계를 유지한다. 유형을 브라우저 입력이나 진입 URL로 결정하지 않는다.
- 한 번 공개되어 대화가 생성된 캐릭터의 유형은 일반 편집으로 바꾸지 못하게 한다. 전환은 기존 세션·발송 큐 처리까지 포함한 별도 운영 작업으로 제한한다.
- 캐릭터의 연락 스위치·활동 시간·기능 플래그·잔액은 유형과 별도로 적용한다. reality라는 이유만으로 발송하지 않는다.
- 사용자 쪽 수신 설정(알림 끄기·통화 거절·야간 차단)은 없다 (2026-09-24 결정). 앱 밖 연락은 항상 받는다. 남은 거절 수단은 브라우저·OS 알림 권한뿐이라, 이 기기가 구독될 때까지 미로 캐릭터 대화방에서 권한을 묻는다. 소개 화면은 운영에서 꺼진 사진·통화를 표시하지 않는다.
- UGC 생성 기본값은 chat. Reality 지정 권한은 초기에는 운영자에게만 허용하는 것을 제안한다. 이는 사용자 확정사항이 아닌 품질 관리 제안이다.
- 기존 캐릭터는 일괄 Reality 전환하지 않는다. 초기 Reality 대상 ID를 명시적으로 선정한다. 기존 대화·기억·잔액은 삭제/재생성하지 않는다.

## 5. 서버에서 반드시 분리할 경로

1. 목록: 홈 추천/공식/커뮤니티/검색/비슷한 캐릭터에서 잘못된 유형 노출 방지.
2. 예약 연락: scheduler 후보 필터 + evaluateSession의 최종 유형 검사.
3. 대화 직후: inlineReality 및 pending reality intent가 일반 캐릭터에서 실행되지 않게 차단.
4. 직접 요청: 사진·통화·Live API/Server Action도 서버에서 자격 검사. 버튼 숨김만으로 끝내지 않는다.
5. 지연 발송: 이미 큐에 든 Push의 재시도 시점에도 캐릭터 자격·사용자 설정 재검증.
6. 관리/UGC: 공개 요청이나 폼 필드 변조로 chat을 reality로 승격할 수 없게 검증.
7. 운영 scheduler에는 결제 승인 지급·만료 정리도 있으므로, 일반 캐릭터 차단을 이유로 Cron 전체를 중단하지 않는다.

## 6. 요금과의 관계

홈/미로는 경험 유형이고 Free/Pro는 이용 자격이다. 서로 다른 축으로 유지한다.
MIRO/ECHO 선택과 Pro 자격을 캐릭터 유형으로 덮어쓰지 않는다. 이번 분리에서 ECHO를 미로 전용으로 제한하는 새 정책은 추가하지 않는다.
미로 진입 자체는 Free도 허용하는 기존 방향을 유지한다. 추가 교감의 제공량·차감량은 사용자 결정값을 기다린다. 가격·환불 등 최신 정책은 MIRO_PRICING_POLICY.md를 따른다.

## 7. 개발 순서와 완료 기준

| 순서 | 작업 | 완료 기준 |
| --- | --- | --- |
| 1 | 유형 모델·마이그레이션·운영 지정 | 기존 데이터 보존, 기본 chat, 허용값·권한 검사 통과 |
| 2 | 서버 실행 경계 | 일반 캐릭터는 Cron·inline·직접 API·큐 재시도 모두 Reality 부작용/차감 없음 |

순서 1~5는 실제 AI 비용 없이 개발·검증 가능하다. 순서 6은 승인된 무료 Gemini 소규모 검증을 활용하되 한도 도달 시 중단한다. 통화/영상 등 미완성 기능은 별도 연결과 검증이 필요하다.

## 8. 공개 전에 남는 결정

- 초기 미로에 배치할 캐릭터 목록: 미정. 공식 캐릭터 전원을 자동 편입하지 않는다.
- Reality UGC 공개 여부: 초기 운영자 관리 제안, 확정 필요.
- Pro/충전 제공량·차감량: 기존 결정 대기 유지.

이번 작업은 기획 문서 작성만 수행한다. 앱 코드·DB·키·운영 예산·배포 설정은 바꾸지 않는다.
