# MIRO · ECHO · 충전소 개발 계획

작성일: 2026-09-15
상태: 계획만 작성. 이 문서로 코드·DB·결제·운영 예산을 변경하지 않는다.

## 1. 목표와 정책 변경

기본 대화는 사용량 걱정 없이 이어가고, 고급 대화와 추가 인터랙션은 구독 제공량 및 충전 사용량으로 이용한다. 사용량이 소진돼도 기존 대화·관계·기억은 유지한다.

최근 사용자 결정에 따라 다음 방향으로 전환한다.

- 기본 모델 이름은 **MIRO**, 고급 모델 이름은 **ECHO**로 한다.
- 요금제 이름은 **Free / Pro**로 유지한다. 모델과 구독 상품을 구분한다.
- MIRO 기본 대화는 월간 사용자 사용량을 차감하지 않는 무제한 방향으로 구현한다.
- ECHO 고급 대화와 사진·음성·영상 등 추가 인터랙션은 공통 사용량을 차감한다.
- **ECHO는 MIRO와 같은 모델을 쓴다.** 차이는 모델이 아니라 한 턴에 들이는 양이다 —
  맥락(최근 대화·기억)을 더 넣고, 더 길게 답하고, 기억·관계 보조 분석을 매 턴 돌린다.
  그만큼 사용량을 더 쓴다. 배수는 `POLICY.chatTier` 에 있으며 원가 측정 후 확정한다.
- 더 이용하려는 사용자를 위한 **충전소 페이지**를 추가한다.
- 바텀시트의 홍보 문구를 줄이고 모델 설명·이용 상태·사용량 진입점 위주로 구성한다.

이 방향은 `MIRO_PRICING_POLICY.md`의 ‘충전팩 없음’, ‘모든 대화를 월간 풀에서 차감’, ‘고급 모델 이름 MIRO Pro’와 충돌한다. **향후 구현은 이 문서의 최신 방향을 기준으로 하며**, 기존 문서 정리는 구현 단계에서 함께 수행한다. 기존 기능이 이미 변경됐다는 뜻은 아니다.

### 구현 시 채택할 추천안 — 세부 정책 확정 필요

- ECHO는 Pro 전용으로 유지한다. 충전만으로 모델 권한을 부여하지 않는다.
- Free 사용자도 실제 제공 중인 추가 인터랙션용 사용량을 구매할 수 있게 한다.
- 월간 제공량을 먼저 사용하고, 부족분을 충전 잔액에서 차감한다.
- 소진 시 ECHO와 추가 인터랙션을 중단하고 MIRO 대화로 이어갈 수 있도록 안내한다. 모델을 몰래 전환하지 않는다.

## 2. 현재 상태와 구현 범위

현재 모델 선택·서버 측 Free/Pro 권한 검사·월간 사용량 예약/확정/환불 구조가 있다. 모델 선택 바텀시트는 아직 MIRO / MIRO Pro 이름을 사용한다. 기본 대화의 월간 차감 면제, ECHO 명칭 변경, 충전소 및 충전 잔액 처리는 아직 구현하지 않았다.

관련 파일:

- `apps/web/app/(main)/chat/[sessionId]/model-picker.tsx`: 모델 선택과 설명
- `apps/web/app/(main)/chat/[sessionId]/model-picker.module.css`: 바텀시트 스타일
- `apps/web/lib/ai/chat-models.ts`: 모델 연결 및 구독 권한 검사
- `apps/web/lib/simulation/turn.ts`: 대화 처리와 사용량 예약
- `apps/web/lib/usage/guard.ts`: 월간 사용량 예약·확정·복구
- `apps/web/lib/payments/`: 기존 구독 결제 처리
- `apps/web/lib/reality/`: 추가 인터랙션 판단·발송
- `packages/db/`: 데이터 구조와 마이그레이션

별도 ECHO 실제 모델, 미디어 기능, 실결제의 출시 검증은 별도로 필요하다. UI나 모의 결제로 실제 기능 제공을 표시하지 않는다.

## 3. 사용자 이용 규칙

| 상황 | 목표 동작 |
| --- | --- |
| MIRO 기본 대화 | 월간 풀과 충전 잔액을 차감하지 않음 |
| ECHO 대화 | Pro 권한 및 사용 가능한 잔액 확인 후 차감 |
| 추가 인터랙션 | 기능 제공 여부·권한·잔액 확인 후 차감 |
| 월간 제공량 소진, 충전 잔액 있음 | 충전 잔액으로 계속 이용 |
| 두 잔액 모두 소진 | 추가 생성 중단, 초기화 시점·충전소·MIRO 선택 안내 |
| 생성 실패 | 예약한 사용량을 원래 출처로 복구 |
| 같은 요청 재시도 | 동일 결과 재사용 또는 안전한 복구, 중복 차감 방지 |
| Pro 만료 | ECHO 권한 회수. 충전 잔액 자체로 권한을 유지하지 않음 |

무료 대화의 ‘무제한’은 사용자 월간 차감이 없다는 의미다. 자동화 남용 방지, 요청 속도 제한, 입력 길이·동시 요청 제한, 서버 API 원가 예산은 유지한다. 공급자 장애나 운영 예산 소진까지 무조건 응답을 보장하는 의미로 광고하지 않는다.

MIRO 대화에서 실행하는 기억·관계 보조 작업은 기본 대화 제공 원가로 취급하되 처리량과 원가를 제한한다. 기본 대화에서 발생했다는 이유로 사진·선톡 등 별도 인터랙션까지 무료로 처리하지 않는다. 사용자가 요청하지 않은 자동 인터랙션이 구매 잔액을 소비할지는 별도 결정 전까지 허용하지 않는다.

## 4. 화면 계획

### 모델 선택 바텀시트

- 제목: **모델 선택**
- MIRO: **편하게 이어가는 일상 대화 · 무료**
- ECHO: **더 깊게 이어가는 대화 · Pro 전용**
- 짧은 안내: **MIRO 기본 대화는 무료예요. ECHO와 추가 인터랙션은 사용량이 차감돼요.**
- 현재 모델 체크 표시, 실제 사용 가능 여부와 준비 중 상태 표시
- 남은 추가 사용량 및 **충전소** 진입 링크
- 미구현 기억 품질·미디어 기능을 현재 제공되는 혜택처럼 표현하지 않음

### 충전소 — 제안 경로 `/recharge`

1. 현재 요금제 및 월간 제공량의 남은 비율·초기화 시점
2. 구매한 충전 잔액을 월간 제공량과 구분해 표시
3. 충전 상품 카드: 가격·제공량·유효기간·구매 버튼
4. 결제 결과 및 구매 내역: 처리 중·성공·실패·취소/환불
5. 충전 사용량으로 이용 가능한 기능과 제한 안내

가격·상품·결제 연결이 정해지기 전에는 상품을 ‘준비 중’으로 표시한다. 가짜 가격, 가짜 잔액, 동작하지 않는 구매 버튼은 넣지 않는다. 충전 잔액은 실제 잔액 API가 마련되기 전까지 임의의 0으로 표시하지 않는다.

진입점은 모델 바텀시트, 내 요금제 화면, 추가 사용량 소진 안내로 한정한다. 기본 대화 중 반복 결제 팝업은 띄우지 않는다.

## 5. 사용량 및 결제 설계

### 기본 대화와 유료 사용량 분리

- 서버가 선택 모델을 확인해 MIRO의 사용자 차감을 면제한다. 클라이언트의 무료 플래그를 신뢰하지 않는다.
- 대화 저장·중복 방지·안전 검사·API 원가 기록은 무료 대화에도 동일하게 적용한다.
- 기존 중요도 기반 대화 차감이 MIRO 무료 대화에 남아 있지 않도록 점검한다.
- ECHO는 공통 풀 소진 이후 기존 continuity 여유분을 통해 계속 호출되지 않도록 한다.

### 충전 원장

기존 월간 사용량 창과 별개로 구매 잔액의 증가·예약·확정·환불·만료 이력을 보존한다. 구체적인 테이블·컬럼은 기존 스키마 검토 후 결정한다.

- 월간 제공량과 충전량에 걸친 예약은 하나의 트랜잭션으로 처리한다.
- 예약마다 각 출처에서 얼마를 사용했는지 기록한다.
- 실패·타임아웃·중복 요청 시 정확히 해당 출처로 복구한다.
- 동시 요청으로 잔액이 음수가 되거나 이중 사용되지 않게 한다.
- 결제 주문 ID·공급자 이벤트 ID를 유일하게 처리한다.
- 브라우저의 결제 성공 화면만으로 잔액을 지급하지 않는다. 검증된 서버 결제 결과로 지급한다.
- 환불·부분 사용 후 환불·결제 취소·차지백·이벤트 순서 역전을 처리한다.
- 구매 잔액의 유효기간과 만료 시 복구 정책은 확정 후 구현한다.
- DB 접근 권한·RLS·감사 기록은 서버 전용으로 검증한다.

## 6. 개발 순서와 완료 기준

### 1단계 — 명칭·설명 정리

MIRO Pro 모델 표시를 ECHO로 바꾸고 바텀시트 문구를 축소한다. 요금제 Pro와 모델 ECHO를 구분한다.

완료 기준: MIRO가 기본 선택이며, ECHO 준비 상태와 구독 권한이 정확히 표시된다. 월 구독료나 고급 모델 성능을 임의로 약속하지 않는다.

### 2단계 — MIRO 기본 대화 차감 면제

대화 모델에 따라 사용량 예약을 분리하고, ECHO·추가 인터랙션에는 기존 제한을 유지한다.

완료 기준: 월간 제공량이 0이어도 MIRO 요청은 사용자 잔액 때문에 거절되지 않는다. ECHO와 추가 인터랙션은 소진 시 차단된다. API 원가 제한·요청 제한·중복 방지·실패 복구는 유지된다.

### 3단계 — 충전소 화면과 진입점

실제 월간 사용량을 읽는 페이지와 진입 링크를 추가한다. 미정 상품은 준비 중으로 표시한다.

완료 기준: 로그인 전 접근, 잔액 조회 실패, 소진 상태, 모바일 표시를 처리한다. 준비 단계에서 결제나 잔액 지급이 발생하지 않는다.

### 4단계 — 충전 원장 및 통합 차감

확정된 상품 정책에 맞춰 마이그레이션과 서버 로직을 추가한다. 월간 제공량 우선 사용, 출처별 복구를 구현한다.

완료 기준: 동시 차감·출처 분할·재시도·복구·월초 초기화 후 구매 잔액 보존을 통합 테스트로 검증한다. 운영 DB 적용 전에 격리 환경에서 검증한다.

### 5단계 — 결제 연동

상품을 서버에서 관리하고 결제 생성, 검증된 결과에 따른 지급, 구매 내역, 환불을 연결한다.

완료 기준: 결제 테스트 환경에서 성공·실패·중복 이벤트·지연·위조·환불을 검증한다. 실제 판매 개시는 상품 및 운영 조건 확정 후 별도 진행한다.

### 6단계 — 출시 검증

실모델 원가·응답 품질, 실제 결제, 부하·모니터링·복구를 검증한다.

완료 기준: 무료 대화 제공 비용이 운영 가능한 수준인지 확인하고, 기능별 출시 조건이 충족된 항목만 활성화한다. 완료한 개발 단위마다 테스트 후 커밋·푸시한다.
