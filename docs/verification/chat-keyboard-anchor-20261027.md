# 채팅 입력·키보드 하단 고정 검증 (2026-10-27)

## 변경

캐릭터챗과 DM 모두, 과거 메시지를 읽어 자동 하단 추적이 멈춘 상태에서 입력창에 포커스하면 마지막 답장 추적을 재개한다. 포커스 직후와 다음 레이아웃 프레임에서 정렬하며, 기존 ResizeObserver가 키보드 애니메이션·입력창 높이 변화 동안 추적을 유지한다. 모델·메뉴 버튼의 포커스는 대화를 이동시키지 않는다. 페이지를 떠나면 이벤트와 예약 프레임을 해제한다.

기존 visualViewport 높이·상하 이동 추적, 키보드 닫힘 처리, 12px 입력창 위 여백과 메시지 화자 전환 간격은 유지한다.

## 검증

- 전용 단위 검사 10개 통과: 입력 시작 재정렬, 메뉴 포커스 제외, 정리, 키보드 열림·중간 높이 변화·Safari 화면 이동·닫힘, 확대와 회전 구분.
- 로컬 브라우저에서 두 화면에 각각 20개 임시 메시지를 넣어, 과거 대화로 스크롤한 뒤 입력창 클릭을 확인했다. 유료 생성은 실행하지 않았다. 임시 메시지 40개는 검증 후 삭제했다.
- DM: 입력 전 바닥까지 894.5px → 입력 후 0.9px, 마지막 메시지와 입력 폼 사이 12.8px.
- 캐릭터챗: 입력 전 바닥까지 1326px → 입력 후 1px, 마지막 메시지와 입력 폼 사이 11.6px. 측정 차이는 화면 배율·부분 픽셀 반올림이다.
- Mac 브라우저 검증과 visualViewport 이벤트 모의 검사다. 실제 iPhone Safari/PWA의 OS 키보드로 직접 검증한 결과는 아니다.

## 언베일 모델 조사

`apps/web/lib/ai/chat-models.ts`는 일반/언베일 목록을 분리해 선택 항목과 과금 견적을 만든다. 언베일은 `MIRO_ADULT_MODEL_REGISTRY`를 사용하고, `packages/providers/src/ai/resolve.ts`는 그 목록 안에서만 선택 모델을 해석한다. 여러 모델을 등록할 수 있는 구조이며, 일반 목록에 모델을 추가하는 것만으로 언베일에 표시되지는 않는다.

이번 변경에는 언베일 모델·공급자·가격·실제 생성 변경이 없다. 다른 모델 연결 전 공급자의 허용 범위, 한국어 품질, 구조화 출력, 스트리밍, 원가를 별도로 검증해야 한다. 모델이 원하는 콘텐츠를 항상 출력한다고 보장할 수 없다.
