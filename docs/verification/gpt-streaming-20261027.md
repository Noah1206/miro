# GPT 캐릭터챗·DM 스트리밍 검증 — 2026-10-27

## 변경

- OpenAI Chat Completions에 `stream:true`, `stream_options.include_usage:true`를 전달한다. 텍스트 delta는 누적 원문으로 기존 `onText` 계약에 전달한다. 마지막 usage-only 이벤트에서 입력·출력·캐시 사용량을 정산하고, finish reason과 `[DONE]`까지 읽는다. 연결 중단을 정상 완료로 간주하지 않는다.
- JSON이나 reasoning/refusal delta를 화면에 직접 표시하지 않는다. 캐릭터챗은 기존 `blockStream`으로 닫힌 대사 블록을 순서대로 보낸다. 엄격한 검토 또는 명시적 대화 선호 검토가 필요한 턴은 기존처럼 최종 검증까지 보류한다.
- DM은 기존 `/api/messages`의 소유권 확인 후 `stream=1`일 때 NDJSON으로 초기 메시지 → 초안 → 최종 저장 메시지를 전달한다. 같은 foreground 요청이 기존 리스 기반 큐 작업을 관찰한다. 보내기 승인 전의 본문은 표시하지 않도록 `send:true`가 선행하는 JSON만 읽는다. 초안은 임시 UI 상태이며 DB 메시지·토큰 잔액으로 취급하지 않는다.
- 기존 읽음 판단·바쁨·답장 지연·재시도 큐·최종 검증·저장 절차는 유지한다. 다른 cron/탭이 이미 작업 리스를 잡았거나 화면이 닫힌 동안 생성된 답장은 다음 조회에서 최종 저장본으로 받는다. 이 경우 이전 생성 조각을 복원하지 않는다.
- 초안 재생성·실패·연결 종료 시 임시 내용을 지운다. 최종 저장본으로 교체하며 중복 말풍선을 남기지 않는다. 메시지 전송 성공 후 즉시 새 스트림 조회를 시작한다. 데이터베이스 스키마와 운영 모델 기본값은 바꾸지 않았다.
- API 스트리밍은 현재 OpenAI 직접 연결에만 적용한다. 다른 OpenAI-compatible 공급자의 기존 요청 방식은 유지한다.

## 검증

50개 집중 검사: GPT SSE 프레이밍, 한글 UTF-8 바이트 경계, CRLF/주석/usage-only 이벤트, 누적 응답 선행 전달, 출력 상한, 필터·잘림·불완전 응답, AbortSignal, 캐릭터챗 블록 스트림, 기존 근거 검토, DM 소유권 확인·진행 중 초안·최종 교체·실패 종료, 기존 턴 예산과 클라이언트 재접속.

루트·웹 타입 검사도 수행했다. UI 문구 변경이나 DB 마이그레이션은 없다.

실제 유료 호출은 GPT 4종의 짧은 캐릭터챗 형식 각 1건 + Luna의 DM 형식 1건, 총 5건이다. 각각 출력 최대 512, 재시도/대체 없음, 전체 $0.10 상한. **사용량 기준 원가 합계 $0.0063615**이며 청구서 대조는 하지 않았다. 결과와 토큰 수는 [원본 측정값](gpt-streaming-20261027.json)에 있다.

이 수치는 짧은 합성 입력의 공급자 어댑터 측정이다. 운영의 긴 프롬프트·검토·DB·브라우저까지 포함한 응답 시간이나 p95를 뜻하지 않는다. 5건 모두 첫 대사 조각이 전체 완료보다 먼저 도착했고, 반환 모델·최종 사용량이 확인됐다.

브라우저에서는 별도의 localhost:8825·로컬 테스트 DB·과금 없는 임시 지연 응답으로 실제 캐릭터챗/DM 컴포넌트를 검증했다. 캐릭터챗의 첫 블록과 입력 중 표시가 전체 완료 전에 나타났고, DM 본문도 순차 증가했다. 최종 교체를 확인한 뒤 검증 서버를 종료하고 임시 분기를 모두 제거했다. 실제 GPT 스트리밍 검증과 UI 합성 응답 검증을 혼동하지 않는다. 운영 사용자의 지갑·대화에는 검증 메시지를 넣지 않았다.
