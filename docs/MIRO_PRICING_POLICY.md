# Miro Free / Pro 요금 정책

## 계좌이체 수납 구현 — 2026-09-16

주문을 받고 운영자가 입금을 확인해 승인하면 지급된다. **판매는 아직 열지 않았다** —
`MIRO_BANK_ACCOUNT` 가 비어 있으면 주문 자체를 받지 않는다.

### 흐름

1. 사용자가 `/recharge` 에서 상품과 **입금자명**을 넣고 주문한다. 서버가 금액·지급량을
   카탈로그에서 확정해 주문에 박고, 6자리 **대조 코드**를 준다.
2. 사용자가 계좌로 보내면서 입금자명 뒤에 그 코드를 붙인다.
3. 운영자가 `/payments` 에서 통장과 금액·입금자명·코드를 대조하고 승인한다.
4. web 앱의 cron(15분)이 승인된 주문을 지급한다.

### 왜 승인과 지급을 나눴나

지급 경로는 `applyPaymentEvent` 하나여야 이중 지급을 막는
`(provider, external_event_id)` UNIQUE 가 단일 지점으로 남는다. 그런데 그 경로는 web 앱
안에 있고 운영 콘솔은 web 을 import 하지 않는다(두 Next 앱을 묶지 않는다). 그래서 운영자는
주문 상태만 `approved` 로 바꾸고 지급은 cron 이 한다. 지급이 몇 분 늦을 수는 있어도 두 번
일어나지는 않는다. 승인됐지만 지급되지 않은 주문은 `settled_at` 이 빌 때까지 매번 다시
시도되므로 실패가 조용히 사라지지 않는다.

### 지키는 것

| | 어떻게 |
| --- | --- |
| 주문 ≠ 지급 | 승인 전에는 아무 잔액도 자격도 늘지 않는다 |
| 이중 지급 | 조건부 UPDATE(동시 승인) + payment_events UNIQUE(동시 지급) |
| 금액 위조 | 금액·지급량은 서버 카탈로그에서만 온다. 주문 뒤 카탈로그가 바뀌어도 주문 당시 조건으로 지급 |
| 오지급 | 입금자명 + 대조 코드로 대조. 자동 대사는 하지 않는다 |
| 권한 | 승인·거절은 `payments.act` (superadmin) 만. reviewer 는 보기만 |
| 추적 | 누가 언제 승인·거절했는지 주문 행과 감사 로그 양쪽에 남는다 |
| 방치 | 대기 주문은 사용자당 하나, 72시간 뒤 만료 |

### 아직 없는 것

자동 입금 대사(은행 연동) 없이 사람이 눈으로 확인한다. 환불은 운영자가 계좌로 직접
보내야 하며 시스템이 회수하는 경로는 `revokeRecharge` 뿐이다. 1인 월 결제 상한과 환불
고지 문구는 판매를 열기 전에 정한다.

## 판매 방식 확정 — 2026-09-16 사용자 결정

이 절이 아래 모든 절보다 우선한다. **구독제를 하지 않는다.**

- Pro 는 **1개월 이용권**이다. 9,900원을 내면 30일간 Pro 자격을 얻고, 기간이 끝나면 만료된다.
  자동 갱신도 자동 결제도 없다. 이어서 쓰려면 다시 산다.
- 결제는 **계좌이체**로 받는다. 정기결제가 필요 없으므로 PG 계약 없이도 성립한다.
- 만료 안내 **2회**: 만료 3일 전, 만료 당일. 각 1회뿐이고 Quiet Hours 를 지킨다.
  사용량 소진은 여전히 알리지 않는다 — 기간 만료만 알린다.
- 화면 문구에서 '구독' 을 **'이용권'** 으로 바꿨다. 해지 버튼은 없앴다 — 갱신될 것이 없으므로
  해지할 것도 없고, 남겨두면 환불로 오해된다.

### 이 변경이 고친 결함

`applyPurchase` 가 `renewalStatus: 'auto'` 로 두는데 만료 sweep 은 `'cancelled'` 인 행만
고른다. 자동 갱신을 없애면서 이걸 그대로 뒀다면 **9,900원을 한 번 낸 계정이 30일 뒤에도
영원히 Pro** 로 남았을 것이다. 구매는 이제 `'cancelled'` 로 시작하고, sweep 은 `expired`
가 아닌 모든 만료 행을 거둔다. 양쪽에 테스트가 있다.

### 아직 남은 것

계좌이체 실제 수납 — 입금 확인, 주문 대조, 중복 지급 방지, 관리자 승인 경로가 없다.
그래서 판매는 여전히 닫혀 있다(`BILLING_NOT_RELEASED`). 환불 기준과 1인 월 결제 상한도
판매 전에 정한다.

## 제공량 확정 — 2026-09-16 사용자 결정

이 절이 아래 모든 절보다 우선한다. **판매 개시를 뜻하지 않는다** — 결제 경로가 없어
`MIRO_RECHARGE_PRODUCTS` 는 여전히 비어 있고 운영은 `BILLING_NOT_RELEASED` 다.

### 근거와 한계

- 기준: 6단계 실측 **텍스트 1턴 = $0.00216** (`gemini-3.5-flash-lite`, 환율 1,400원 기준 약 3원).
  `textRP` 가중치 1 을 이 원가에 맞춘 것이다.
- **미디어 가중치는 실측이 아니다.** `photo` 10, `faceCast` 15, `videoCallPerMinute` 20 등은
  추정치이며 운영에서 강제 비활성화 상태라 잰 적이 없다. 미디어를 여는 시점에
  `pnpm ai:cost` 로 재측정하고, 어긋나면 **가중치를 고친다** — 확정한 제공량 숫자가 아니라.
- 충전 최고가를 50,000원까지 둔 것은 더 사고 싶은 사용자를 막지 않기 위해서다. 실제
  판매 전에 1인 월 결제 상한과 환불 기준을 함께 정한다.
- 남용 한도(`AI_USER_MONTHLY_BUDGET=$3`, `AI_USER_MONTHLY_LIMIT=3000`)는 이 제공량과 별개
  층이다. 무차감인 MIRO 기본 대화의 실질 상한은 계속 이쪽이 맡는다.

### 이 절로도 정해지지 않은 것

초기화 기준(월초 고정 vs 결제일), Free 의 충전 구매 허용 여부, Pro 해지 후 잔액 처리,
선톡 차감 활성화 시점은 그대로 미정이다.

## 확정한 방향

Miro의 가치는 내 삶 속에 계속 존재하는 캐릭터와 관계를 유지하는 경험이다. 전환 흐름은 **Free → Reality Interaction 경험 → 관계 형성 → Pro → 더 깊고 빈번한 Reality**다. Pro의 구매 이유는 메시지 횟수 증가에 한정하지 않고 캐릭터가 내 세계에서 더 많이 살아 움직이는 경험으로 설명한다.

- 요금제는 MIRO Free / MIRO Pro 두 가지다. 별도 Reality Credit 충전팩, 코인 지갑, 턴별 구매 상품은 판매하지 않는다.
- Free도 텍스트 RP, 관계 변화, 선톡, 시간 기반 Reality Interaction, 기본 이벤트, 가끔 사진·특수 Interaction을 경험해야 한다. 무료 무제한을 약속하지 않는다.
- Pro는 기능 잠금 해제보다 깊이와 빈도를 늘린다. 더 긴 기억, 더 많은 Reality Interaction과 선톡, 사진·음성·영상통화·Live Scene·Face Cast·복잡한 Event·NPC Interaction을 하나의 월간 Usage Pool 안에서 처리하는 것이 목표다.
- 고비용 기능의 출시 시점은 실제 구현·안전성·원가 검증에 맞춘다. 미구현 기능을 판매 중인 혜택으로 표시하지 않는다.
- 기능별 크레딧 단가, 토큰 수, 모델별 턴 요금을 사용자에게 표시하지 않는다. 내부 원가 가중치는 상품 표현과 구분한다.
- 사용량은 **이번 달 Reality 사용량**, 진행 막대, **78% 사용**처럼 표시한다. 사용한 비율과 남은 비율을 명확히 구분한다.
- 실제 공급자 이름 대신 MIRO / MIRO Pro 모델을 선택한다. MIRO가 기본이며 MIRO Pro는 유효한 Pro 구독과 별도 연결 모델이 필요하다. 보조 작업은 내부에서 라우팅한다.
- 답변 스타일 메뉴는 제거한다. 별도 턴 결제 UI는 추가하지 않는다.

## 기존 구조와 연결

월간 풀은 기존대로 한국 시간 매월 1일 00시 초기화한다. 정상 완료한 요청은 서버 원장에 확정하고 실패한 요청은 사용자 사용량을 복구한다. 소진 시 기존 대화·관계·기억 상태를 삭제하지 않는다.

사용자 Usage Pool과 운영자의 API 원가 예산은 별도다. 공급자 무료 할당량은 사용자 무제한 이용 약속이 아니다. 이 정책 기록만으로 운영 예산이나 결제를 활성화하지 않는다.

## 아직 미정인 사항

- Pro 가격과 결제 주기별 상품 구성.
- Free / Pro 월 제공량. 현재 100 / 1,000은 개발 임시값이다.
- 기능별 내부 가중치와 실제 원가.
- 요금제별 기억 범위, 선톡·이벤트·미디어 빈도의 구체적인 차이.
- 캐릭터가 먼저 발생시킨 Interaction의 사용자 풀 차감 여부와 상한. 기존 단순 선톡은 무차감 기본값이며 자동 유료 차감으로 바꾸지 않는다.
- 한도 근접 안내 시점, 소진 후 응답 유예·예약량 여부. 현재 continuity 옵션은 기본 비활성이다.

6. 고비용 미디어는 준비된 기능부터 같은 Usage Pool에 연결.

## 2026-09-15 모델 선택 변경

사용자 최신 결정으로 채팅 헤더의 답변 스타일 메뉴를 제거하고 `MIRO` / `MIRO Pro` 모델 메뉴를 표시한다. 기본 선택은 `MIRO`(무료형)다. Pro 모델은 유효한 Pro 요금제와 별도 연결 모델이 모두 있을 때만 선택 가능하며, 매 요청마다 서버가 권한을 재확인한다. 모델 선택은 월간 Usage Pool을 대체하거나 별도 턴 과금을 추가하지 않는다.

서버의 `MIRO_CHAT_FREE_MODEL_ID` / `MIRO_CHAT_PRO_MODEL_ID`는 Model Registry의 ID를 지정한다. 미지정 시 활성 dialogue 모델 중 무료형은 non-premium, Pro는 premium을 사용한다. 동일 모델을 두 상품으로 노출하지 않는다. Pro 모델이 없으면 준비 중으로 표시한다. 실제 모델 검증과 운영 예산 0 유지 지시는 그대로 유효하다.

### 2026-09-15 갱신 — 위 문단은 더 이상 구현과 맞지 않는다

고급 모델은 `ECHO` 로 이름이 바뀌었고, **MIRO 와 같은 모델을 쓴다.** 두 상품을 가르는 것은
모델이 아니라 한 턴에 들이는 양이다 — ECHO 는 맥락을 더 넣고, 더 길게 답하고, 기억·관계
보조 분석을 매 턴 돌린 뒤 그만큼 사용량을 더 쓴다. 등급 값은 `POLICY.chatTier` 에 있다.

따라서 `MIRO_CHAT_FREE_MODEL_ID` / `MIRO_CHAT_PRO_MODEL_ID` 는 없어지고 `MIRO_CHAT_MODEL_ID`
하나가 두 상품이 공유할 모델을 고정한다. premium 모델이 없어도 ECHO 는 준비 중이 아니며,
Pro 요금제만 확인한다. MIRO 기본 대화는 월간 사용량을 차감하지 않는다 —
자세한 내용은 `MIRO_ECHO_RECHARGE_PLAN.md` 를 따른다.
