# 2026-10-15 대화 역할 분담·목소리·타이핑

## 운영 배치

`ai/models/miro-role-split.json`을 `MIRO_MODEL_REGISTRY`로 사용한다. JSON 파일을 수정하는 것만으로 운영 환경변수가 바뀌지는 않는다. 배포 전 환경변수 반영과 다시 읽기 검증이 필요하다.

- Gemini 3.6 Flash (`gemini-flash`): 대사, 계획, 검증, 캐릭터 컴파일, 자기 삶, 사건·세계·이미지 지시.
- Gemini 3.5 Flash-Lite (`gemini-flash-lite`): 의미 사건·관계 분류, 기억 추출·요약. 기존 실행 조건을 유지한다.
- Claude Sonnet 5.5: 명시한 장애 예비. 사용 가능한 예비를 직접 설정하면 GPT 예비를 자동 추가하지 않는다. 예비 미설정일 때의 기존 GPT 추가 동작은 유지한다.
- `MIRO_CHAT_MODEL_ID=gemini-flash`, `GEMINI_MODEL=gemini-3.6-flash`. 언베일 전용 레지스트리는 변경하지 않는다.

처음 시도한 3.8 Flash는 실제 운영 계획·대사에서 각각 20초 초과했고 간단한 독립 호출도 30초 초과했다. 3.6 Flash는 독립 호출 약 4초, 실제 운영 계획 5.34초·대사 5.924초에 성공했다. 3.6에서도 일시적인 503이 관찰됐다. 기존의 제한된 재시도·장애 예비를 유지한다.

현재 Flash 가격은 입력 $0.75 / 출력 $3.75, Lite는 $0.30 / $2.50 (백만 처리 토큰당)이다. **Flash의 현재 한시 가격은 2026-12-31까지이므로 2027-01-01 전에 레지스트리 가격을 다시 검증·반영해야 한다.** 출처: [Google 공식 가격](https://ai.google.dev/gemini-api/docs/pricing.md). 비용·사용량 보호 장치를 우회하지 않는다.

## 대화 방식

작성된 말끝·호칭·문장 길이·반말/존대·직설/우회 방식을 유지한다. 매 턴 상황·속마음·대사를 모두 채우던 강제를 제거했다. 입력을 되풀이하고 감사·사과·질문을 붙이는 틀 대신 직전 질문의 답을 받아 캐릭터의 현재 목적과 행동을 이어가게 했다. 명시적인 거절, 사용자 행동 결정권, 관계·세계 상태 검증은 유지한다.

프롬프트 추적: `voice-conversation-v2`, `agency-planner:v10`, `agency-dialogue:v5`.

공개 설정만 사용한 별도 실제 생성 점검에서 서이안·구만석·백도현의 말투와 호칭을 비교했다. 각각 5.388초, 3.637초, 7.265초에 3.6 Flash가 응답했다. 이 점검은 전체 자율성 파이프라인 평가가 아니며 모든 답변의 문체 품질을 보장하지 않는다.

## 화면

- 새 스트리밍 답변도 기존 `CharacterBubble` / `TypedText` 경로를 사용한다. 대사·행동·상황·속마음을 순서대로 표시한다.
- 요청·시도별 재생 키를 저장 메시지 ID와 연결해 저장 완료/refresh에서 타이핑이 재시작하거나 한꺼번에 펼쳐지지 않게 했다. 재생 중 속도 변경도 현재 문단을 재시작하지 않는다.
- 일반 새 답변은 문단당 3초, 여러 문단의 기본 합산 목표 10초로 조정했다. 구두점 쉼과 공급자 수신 간격은 별도다. 기존 인트로 읽기 속도, 과거 기록 즉시 표시, 모션 줄이기 설정은 유지한다.
- 자동 스크롤·사용자의 위로 읽기 제어·미로 기본 테마의 실제 프로필 사진은 유지한다.
- 그리드 이름 48→28px, 설명 14px, 해시태그 10px. 태그 개수 3~5개 유지.

## 재시도 한도 수정

실제 QA에서 공급자의 사용량 미보고 실패가 사용자 턴 한도에 추정 비용으로 남아, 정상 복구 호출을 막는 현상을 발견했다. 서버 BudgetGuard의 보수적 비용 예약은 유지하되, 실패한 미보고 호출은 고객의 답변 복구 여유를 소진하지 않도록 수정했다. 측정된 비용의 합산 한도, 출력·입력 상한, 전역 예산, 재시도 횟수는 유지한다. 회귀 테스트로 연속 실패 후 복구와 측정 비용 상한을 확인한다.

## 운영 확인 결과

운영의 별도 QA 방에서 실제 입력 3건이 새 턴으로 저장됐으며, 중간 1건은 생성 한도 실패로 저장·차감되지 않았다. 복구 수정 후 해당 입력을 보관된 그대로 다시 전송해 성공했다. 마지막 요청은 Flash-Lite 기억 추출 1.058초, Flash 계획의 503 세 번 후 Sonnet 예비 계획 7.45초, Flash 대사 8.044초로 완료됐다. 주 모델의 실제 성공과 예비의 실제 복구를 모두 확인했다. 공급자 503이 이어지는 동안에는 응답이 지연될 수 있다.

화면에서 `코끝에` → `코끝에 걸린 안경을 검손가락으로 느리게 고쳐 쓰며 말을 아낀다.`의 행동 서술과 별도 대사 문장이 점진적으로 나타나는 것을 확인했다. 최종 저장·재진입 뒤 재타이핑이나 중복 메시지 없음, 스크롤 바닥 차이 0~0.5px, 입력 공란·활성화, 다음 입력 시 전송 활성화, 실제 프로필 사진을 확인했다. 마지막 프런트엔드 수정은 연결 복구 시 서버 중복 방지 요청 ID는 유지하면서 시각 재생 키만 새로 만드는 것이다.

QA 한정 지급 300 중 40 사용, 미사용 260 회수, 종료 잔액 0·남은 예약 0. 지급 전의 기존 충전 행은 변경 없음을 비교 확인했다. 실제 결제나 일반 사용자 대상 알림 발송은 수행하지 않았다.
