# 미로 자율성 중심 응답 경로 전환 계획

2026-09-29 · 기준 `main@69de8c5` · 상태: 계획 수립, 구현·운영 전환 전

기존 설계 `character-agency-plan.md`의 후속 실행 계획이다. 기존 설계와 과거 평가 결과는 이력으로 보존한다. 이 문서의 목표·수치·신규 파일·스키마는 구현 제안이며 완료 사실이 아니다. 현재 운영 모델 설정, 자율성 코호트, 적용된 DB 마이그레이션은 이번 계획에서 조회하지 않았다.

## 1. 목표와 범위

미로 캐릭터는 자신의 설정·관계·경험·목표를 근거로 행동을 선택하고, 대사는 그 선택을 표현한다. 기존 채팅·문자·문자 통화·선연락·기억을 보존하면서 자율성 경로를 미로의 기본 경로로 만든다. 일반 캐릭터는 기존 대화 중심 경험을 유지한다.

성공은 다음 사용자 경험으로 판단한다.

- 성격이 다른 캐릭터가 같은 상황에서 서로 다른, 설정에 근거한 선택을 한다.
- 약속·거절·취소·정정이 다음 대화와 선연락에 이어진다.
- 말로 약속한 것, 실행을 시도한 것, 실제 완료한 것을 구분한다.
- 관계 변화가 공개할 정보·거리·말투·선택에 반영된다.
- 장소·시간·사건이 설명 없이 바뀌지 않는다.
- 기존 기억과 긴 장면 경험을 잃지 않으며 응답 지연과 원가를 측정할 수 있다.

새 Decision Engine, Belief/Goal 엔진, 모델 라우터, 평가 플랫폼을 만들지 않는다. 벡터 DB, 신규 감정 축, 24시간 LLM 시뮬레이션, 자체 SLM, 가격·상품 변경, 화면 개편은 이번 범위 밖이다. 시간 경과 정산과 하이브리드 검색은 후속 과제로 남긴다.

## 2. 코드에서 확인한 출발점

| 영역 | 현재 구현 | 전환 시 해결할 차이 |
|---|---|---|
| 대화 입구 | `apps/web/lib/simulation/turn.ts`: 소유권·중복 방지·사용량 예약·저장·환불 | 공통 처리 유지, 정책은 서버에서 한 번 확정 |
| 기본 엔진 | `packages/engine/src/orchestrator.ts`: 검열 → 의미 분석 → 규칙 관계/기분 → 대사 → 검열/기억 대기 | 자율성 엔진과 관계·감정 갱신을 중복 실행하지 않기 |

| 기억 | `lib/ai/memory.ts`, `task-router.ts`: SQL 조회·추출·12턴 요약 | 현재 추출은 생성과 병렬이지만 반환 전에 기다림. 출처와 갱신 순서 보강 |
| 저장 | `simulation/commit.ts`: 메시지·관계·기억·사용량 원자적 저장, 버전 충돌 확인 | 인과 기록·후처리 작업도 같은 원자성 보장 |

9/24 평가 문서에는 후속 수정 전후 결과가 함께 있다. 과거의 성공·실패율은 현재 성능으로 인용하지 않고 최신 커밋으로 재측정한다. 특히 취소 후 발송, 계획 스키마 거부, 높은 지연·원가의 재현을 우선한다.

## 3. 설계 결정

### 3.1 정책은 경험·등급·채널을 분리한다

`TurnPolicy`는 서버가 구성하는 작은 명시적 객체로 시작한다. 범용 워크플로 엔진이나 임의 단계 플러그인 시스템을 만들지 않는다.

| 축 | 값 | 결정하는 것 |
|---|---|---|
| 경험 | 일반 `chat` / 미로 `reality` | 자율성, 세계 변화, 선연락 가능 범위 |
| 응답 등급 | MIRO / ECHO | 맥락·출력 예산, 추출 빈도, 장면 표현 깊이 |
| 채널·트리거 | 장면 / 문자 / 통화 / 백그라운드 | 현재 실행 가능한 행동과 표현 방식 |
| 운영 상태 | 정책 버전·준비 상태·코호트 | 사용할 경로, 중단·복구 방식 |

일반 캐릭터는 MIRO/ECHO 어느 등급에서도 자율 세계 변경·선연락을 할 수 없다. ECHO는 행동 권한을 늘리지 않는다. 문자와 통화는 채널에 맞는 길이를 유지하며 긴 장면을 억지로 출력하지 않는다. 입력 검열과 출력 검열은 일반챗에도 유지한다. 저장과 발송 직전에 최신 권한을 재검사한다.

### 3.2 같은 사건은 관계·감정에 한 번만 반영한다

기본 경로의 의미 사건과 자율성 경로의 appraisal을 공통 관측 계약에 연결한다. 행위자·대상·출처·발언/관측 구분·시점·부정/인용/가정 정보를 보존한다.

- 일반챗: 현재 의미 분석과 규칙 계산을 유지한다.
- 미로: 기존 자율성 planner의 근거 기반 해석을 사용하고, 승인된 해석에 대해 서버 전이 정책이 변화의 허용 여부·범위·중복을 결정한다.
- 같은 입력에 기존 `codeDelta`와 자율성 `relationshipDelta`를 더하지 않는다. 관계를 갱신하는 소유자는 정책별로 하나다.
- 미로의 관계 단계 전환과 기분 표현도 한 전이 결과에서 파생한다. 기존 기분과 자율성 affect를 각각 독립 저장해 충돌시키지 않는다.
- 의미 분석을 후처리로 보내지 않는다. 초기 연결 시 기존 호출을 재사용하고, planner와 실제로 겹치는 분석은 평가 후 통합할 수 있다. 추가 LLM 호출부터 만들지 않는다.
- 자존심 같은 성격 규칙은 선택의 근거다. 서버가 일률적으로 연락·사과를 금지해 캐릭터의 상황별 예외와 판단을 덮어쓰지 않는다.

### 3.3 상태 변경은 표현 전에 승인한다

목표 경로:

```text
요청·소유권·중복 확인 → 정책 결정 → 상태·기억 조회 → 사용량 예약
→ 입력 검열 → 관측/해석 → 관계·감정/믿음·목표 후보
→ 행동 선택 → 상태 전이 승인 → 맥락 구성 → 대사 생성
→ 출력 검열 + 승인된 행동/상태와의 일치 검증
→ 버전·권한 재검사 → 트랜잭션 저장 → 응답
                                  └ 기억 작업 등록 → 후처리
```

대사를 만든 뒤 잘못된 장소 변경만 버리면 “도착했다”는 말과 DB가 어긋난다. 미로에서는 승인된 행동·전이를 먼저 렌더러에 주고, 승인 범위를 벗어난 완료 서술을 검증한다. 생성 과정에서 나온 추가 세계 제안은 그 자리에서 승인하지 않는다. 거부 시 기존 상태를 유지하고 제한된 재생성 또는 명시적 실패로 처리한다. 재생성은 최대 1회, 같은 요청 예산에 포함한다.

초기 세계 전이 범위는 기존 장소·장면·사건 상태 변경으로 제한한다. 이동 의도와 도착 완료는 구분하되 범용 이동 시뮬레이터는 만들지 않는다. 서버가 확인할 수 없는 이동은 의도/진행으로만 기록하고 도착을 확정하지 않는다. 서사 속 시간 이동은 명시된 장면 전환 근거로 처리하며 실제 시간의 연락 예약으로 변환하지 않는다. 새 세계 행동 계약은 필요한 최소 유형만 기존 자율성 후보 계약에 추가한다.

### 3.4 인과 기록은 기존 결정·사건 기록에 연결한다

기존 `characterDecisions`, `events`, action receipt를 재사용한다. 공통 상태 변경 이력이 없는 부분에만 작은 전이 원장을 추가한다. 전체 이벤트 소싱으로 상태를 재구축하지 않는다.

전이 원장의 최소 제안 필드: 세션, 요청/트리거, 결정 참조, 원인 메시지·사건 ID, 행위자/대상, 정책·캐릭터 버전, 승인된 변경 필드의 전후 값, 적용 규칙, 상태 버전, 실제/서사 시각 구분, 실행 결과 참조. 거부·보류는 고정된 사유 코드로 기록한다.

- 원장은 서버가 승인한 결과를 기록한다. 모델이 제출한 자유 형식 로그를 사실로 저장하지 않는다.
- 요청/결정과 효과 순번에 고유 키를 두고 재시도 시 중복 관계 변화·이벤트 생성을 방지한다.
- 대화 저장, 푸시 작업 등록, 전송, 기기 도달, 사용자 열람을 구분한다. 제공자가 확인하지 못하는 도달 상태를 만들어내지 않는다.
- 인과 조회는 한 세션의 변경 필드와 근거를 확인하는 작은 내부 조회부터 제공한다. 새 대시보드는 만들지 않는다.
- 원문 대화와 모델의 숨은 추론은 복제하지 않는다. 삭제 정책은 기존 소유 세션에 연동하고, 삭제 후 참조가 남아 개인 데이터를 재노출하지 않도록 검증한다.

### 3.5 기억 후처리는 내구성·순서·정정 보호를 함께 구현한다

응답 트랜잭션에서 메시지·상태·전이 기록·사용량과 `memory_job`을 함께 저장한다. 추출과 요약 결과는 후처리한다. 대사 모델이 낸 기억 후보도 출처 없는 동기 저장 우회로로 남기지 않는다.

- 작업은 메시지 ID, 해당 턴/시퀀스 상한, 작업 종류·버전으로 식별한다. 재시도할 때 미래 메시지를 입력에 섞지 않는다.
- 기존 outbox의 임대·재시도·기한 만료 회수 패턴을 재사용하되 푸시 작업 테이블에 기억을 섞거나 범용 큐를 새로 만들지 않는다.
- 한 세션의 기억 갱신은 순서를 보장한다. 요약은 `throughSequence`와 버전 비교로 최신 요약을 덮어쓰지 못하게 한다. 앞선 작업이 실패하면 요약이 해당 범위를 누락한 채 성공 처리되지 않도록 한다.
- 추출은 중복 없는 결과 저장과 작업 완료를 같은 트랜잭션에서 처리한다. 외부 모델 호출은 재시도될 수 있으므로 호출 비용까지 정확히 한 번이라고 주장하지 않는다.
- 커밋 후 빠른 작업 실행을 시도하고 주기적 회수 작업을 둔다. 기존 15분 크론만으로 기억 신선도를 충족한다고 가정하지 않는다. 즉시 실행이 유실돼도 DB 작업은 남아야 한다.
- 다음 턴은 최신 메시지를 우선 사용한다. 정정·약속 취소는 해당 턴에서 관련 믿음/행동을 즉시 재판단한다. 후처리가 최신 정정까지 따라오기 전에는 충돌 가능성이 있는 옛 기억을 확정 사실로 공급하지 않는다.
- 미로의 즉시 행동에 필요한 믿음·목표·취소는 동기 상태다. 장기 기억 추출과 요약만 후처리로 옮긴다.
- 원문 메시지 출처와 관측 권한을 확인한 기억만 자율성 맥락에 넣는다. 출처 없는 옛 기억을 관측 사실로 일괄 승격하지 않는다. 복원 가능한 출처는 연결하고 나머지는 불확실한 과거 기록으로 구분한다.
- 사용자 삭제·세션 삭제·제한 이후에는 작업을 취소하고 결과를 기록하지 않는다. 실패 작업은 제한된 재시도 후 운영에서 재처리 가능한 상태로 남긴다.
- 후처리 원가도 원래 턴/사용자에 연결하고 전체 AI 예산에 포함한다. 사용자 크레딧을 추가로 차감하지 않는다. 후처리 실패로 이미 전달된 정상 답변을 실패 처리하거나 중복 환불하지 않는다.

## 4. 실행 순서와 완료 기준

각 단계는 독립적으로 리뷰·검증 가능한 변경 단위다. 구현 시 최신 Git 상태를 확인하고 별도 작업 브랜치/체크아웃을 사용한다. 일정은 0단계 결과 이후 산정한다.

| 단계 | 변경 범위 | 완료 기준 | 의존 |
|---|---|---|---|
| 0. 기준선·계약 | 평가 도구와 기능 보존 목록, 호출별 출처/시간/비용 연결 | 최신 소스로 기존/자율성 비교, 실패 재현, 운영 미확인 항목 분리 | 없음 |
| 1. 정책 분리 | 서버 정책 resolver, `turn.ts`, `orchestrator.ts`, 채널 입구 | 동작 변경 없이 일반/미로 × MIRO/ECHO 경계 통과 | 0 |
| 2. 전이·인과 기록 | 순수 전이 정책, 작은 원장, `commit.ts` | 이중 관계 변화·근거 없는 완료·중복 이벤트 0, 변경 이유 조회 가능 | 1 |
| 3. 기억 후처리 | 출처 보강, 작업 테이블·워커·회수, 요약 순서 | 유실/중복/역순 시험 통과, 직후 정정 회수 유지, 지연 비교 | 2 |
| 4. 자율성 통합 | 관측·appraisal 연결, 맥락·표현, 세계 전이 | 짧은 응답 강제 제거, 일반챗 보존, ECHO·장면·문자·통화 계약 충족 | 2, 3 |
| 5. 채널 일관성 | 선연락·예약·취소·결과 수신 연결 | 약속 취소 후 발송 0, 새 입력과 발송 경합 처리, 생활 리듬 유지 | 4 |
| 6. 기본 경로 전환 | 세션별 정책 버전, 점진 전환·복구 | 제한적 실제 평가와 운영 관측 통과 후 신규 미로 세션 기본 적용 | 5 및 운영 게이트 |

0단계에서 현재 사용 가능한 평가 진입점과 예산 보호를 확인한다. 기존 README의 리플레이와 baseline 실호출 경로 설명이 다르므로 `--live`가 항상 가능하다고 가정하지 않는다. API 키를 읽지 않는 합성 평가부터 수행한다. 현재 운영 `world_update` 지원 여부도 실제 전환 전에 확인한다.

1단계는 단순 추출이다. 이때 자율성 활성화, 모델·가격 변경, 기억 비동기화까지 섞지 않는다. 2단계의 제한된 전이 정책은 미로 후보 경로에서 먼저 검증하고 기존 일반챗 동작을 일괄 제한하지 않는다.

4단계의 맥락 우선순위는 서비스 경계·캐릭터 명시 설정 → 현재 입력·승인된 결정 → 현재 장소/사건·유효 목표/정정 → 최근 대화 → 출처 있는 관련 기억 → 보조 예시 순으로 시작한다. 수식처럼 모든 상황에 고정하지 않고 모드별 필수 항목을 선언한다. 최종 계획·근거를 붙인 뒤의 전체 프롬프트까지 예산을 재검사한다. 근거 없는 NPC 정보는 새로 허용하지 않고 관측자·시각 출처가 연결된 것만 복구한다.

## 5. 검증 시나리오와 게이트

### 계약 검증 — 반드시 통과

| 시나리오 | 기대 결과 |
|---|---|
| 일반 캐릭터 + ECHO | 답변 예산만 변경, 세계/선연락 권한 확대 없음 |
| 같은 요청 재전송, 저장 직전 중단 | 답변·과금·관계·작업·원장 중복 없음 |
| 채팅과 선연락 동시 실행 | 최신 버전/권한 재검사, 오래된 결정 커밋 거부 |
| 칭찬과 가정/인용/부정된 고백 | 실제 사용자 행위만 근거로 반영, 같은 사건 이중 적용 없음 |
| 약속 → 취소 → 기한 도래 | 취소 이후 새 발송 시작 없음, 이미 시작된 외부 발송 결과는 별도 기록 |
| “이제 커피 안 좋아해” 직후 다음 턴 | 후처리 지연 중에도 옛 취향을 현재 사실로 단정하지 않음 |
| 12턴 요약 + 늦은 과거 작업 | 최신 사실/요약을 과거 결과가 덮어쓰지 않음 |
| 직장 회의 중 사용자 집 도착 제안 | 허용 근거 없으면 도착 상태·완료 서술 모두 차단 |
| 내레이터 비밀·NPC 주장 | 캐릭터의 관측 사실로 자동 승격되지 않음 |
| 작업 임대 만료·중복 실행·모델 오류 | 재처리 가능, 효과 중복 없음, 예산 상한 유지 |
| 사용자/세션 삭제 중 후처리 | 이후 기억/원문 재생성·알림 없음 |
| 엔진 전환 후 복구 | 관계·대화 유지, 목표 이중 실행 없음, 재전환 시 근거 정합성 확인 |

단위 테스트는 순수 정책·전이, 통합 테스트는 격리된 로컬 `_test` DB의 실제 저장·워커·경합, 브라우저 검증은 로그인 → 대화 → 새로고침 → 기억/장면 지속 및 문자/통화 경로에 집중한다. 운영 `.env`를 테스트 DB로 사용하지 않는다. 합성 장기 리플레이는 데이터 정합성 증거이며 실제 성격 품질로 보고하지 않는다.

### 실제 답변 품질·성능 — 제한적 확대 판단

아래는 초기 제안 게이트다. 현 버전 기준선을 만든 뒤 비용/시간 절대 상한과 실험 예산을 고정하고 결과를 본 뒤 유리하게 바꾸지 않는다.

- 대비되는 성격 3명 이상 × 20턴 × 2회(후보 최소 120턴), 같은 사용자 시나리오의 기존 경로 대조. 인사뿐 아니라 갈등·정정·거절·약속·취소·채널 전환을 포함한다.
- 후보 턴 성공률 98% 이상, 비교군 대비 악화 여부 별도 보고. 작은 표본을 운영 신뢰도 보장으로 해석하지 않는다.
- 취소 후 신규 발송, 권한 없는 세계 변경, 허위 완료, 타 사용자 근거 노출, 중복 과금은 0건. 발생 시 확대 중단.
- 사람 평가에서 인물 일관성·선택의 타당성·기억 회수·장면 연속성을 각 5점 척도로 비교한다. 각 항목 중앙값이 기준선보다 낮지 않고, 사전에 정한 핵심 행동 시나리오의 80% 이상에서 근거와 행동이 일치해야 한다. 길이만 늘어난 것을 개선으로 채점하지 않는다.
- 초기 목표는 후보 p95가 같은 조건의 기준선 1.25배 이내, 성공 턴당 총원가는 2배 이내다. 원가에는 실패·재시도·기억 후처리를 포함하고 컴파일과 선연락 비용을 별도 표시한다. 실제 상품 예산보다 크면 더 낮은 한도를 적용한다. 미달 시 기본 전환을 보류하고 원인을 좁힌다.
- ECHO는 긴 글 자체가 아니라 과거 사건 회수·장면 유지·감정 표현의 맥락 적합성으로 비교한다. 이 계획에서 차감량은 바꾸지 않는다.
- 기억 워커는 정상 상태 작업 완료 p95 10초 이내를 초기 목표로 측정한다. 회수 작업의 최대 지연도 따로 측정한다. 이 목표를 달성할 실행 환경이 없으면 후처리 완료를 기다리지 않는 정합성 보호와 운영 대안을 확인한 뒤 적용한다.

## 6. 전환·복구

1. 스테이징/격리 환경에서 추가 스키마와 구·신 코드 호환성을 검증한다. 운영 반영 시 스키마 → 호환 코드 → 워커 확인 → 제한적 세션 순서로 진행한다.
2. 제품의 목표 기본값과 운영 코호트를 분리한다. 현재 production은 명시 세션 목록만 허용하며 `*`는 전체 활성화 방법이 아니다. 신규 세션 기본 적용은 별도 정책 버전으로 구현한다.
3. 처음에는 명시한 테스트 세션만 전환한다. 계획 컴파일이 준비되지 않으면 기존 대화는 유지하되 새 자율행동은 보류하고 이유를 기록한다. 준비된 엔진의 실행 오류를 기존 생성으로 숨겨 성공률에 섞지 않는다.
4. 채팅·문자·통화·선연락이 같은 세션 정책 버전을 사용하도록 한 경계에서 전환한다. 기존 세션은 현재 관계/세계/대화와 작성자 버전을 유지하며 전환 표시를 남긴다. 과거 기억을 재해석해 관계를 다시 계산하지 않는다.
5. 제한적 세션에서 성공률·지연·원가·기억 지연·발송 결과를 확인한 뒤 신규 미로 세션 기본값으로 확대한다. 기존 장기 세션은 출처·미완료 목표 정리 이후 별도 확대한다.
6. 중단 시 정책 라우팅과 새 자율 발송을 멈춘다. 기록·목표·대화·추가 스키마를 삭제하지 않는다. 기존 대화 경로로 복구할 때 자율성 상태는 보존/정지하고, 그동안 새로 쌓인 메시지를 재전환 전에 반영한다. 동기 기억과 워커가 동시에 쓰지 않도록 작업별 버전·단일 작성자를 유지한다.
7. 취소·권한·비용 게이트 위반은 즉시 확대 중단 사유다. 중단 시점 이후 발송 claim은 차단하고 이미 시작된 외부 전송은 결과를 기록한다. 외부 전달의 취소를 보장한다고 표현하지 않는다.

운영 전환 직전 필요한 결정은 실모델 실험의 전체 예산, 대상 세션, 운영 지연·원가 상한이다. 계획 작성이나 로컬 구현을 운영 설정·실계정 발송·배포 승인으로 간주하지 않는다. 지금은 그 결정을 기다리느라 계약 정리와 격리 검증을 멈출 필요가 없다.

## 7. 첫 구현 묶음

첫 묶음은 **0단계 + 1단계**다. 산출물은 최신 경로 비교표/실패 재현, 호출별 추적 누락 보강, 경험·등급·채널 정책 resolver, 기존 입구 연결, 동작 보존 테스트다. 플래그 기본값과 사용자 화면은 이 묶음에서 변경하지 않는다.

그다음 **2단계 전이·인과 기록 → 3단계 기억 후처리 → 4·5단계 자율성/채널 통합 → 6단계 검증 후 전환** 순서로 진행한다. 각 단계의 완료 여부는 코드, 로컬 검증, 실제 모델 평가, 운영 반영을 분리해 기록한다.
