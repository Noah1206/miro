# 대사별 음성 연출 연결

2026-10-24 구현. 유료 모델 호출·학습·운영 배포는 실행하지 않았다.

## 생성과 저장

기존 대화 생성 한 번에 각 `dialogue` 블록의 `delivery`를 함께 생성한다. 추가 연출용 LLM 호출은 없다. 일반 및 agency 응답 스키마와 프롬프트에 반영했다.

```json
{"type":"dialogue","speaker":"서도윤","text":"나 여기 있어.","delivery":{"emotion":"hurt","tone":"soft","pace":"slow","intensity":"soft","pauseAfterMs":450}}
```

공유 계약은 `packages/config/src/voice-delivery.ts`, 검증은 `packages/engine/src/proposal.schema.ts`에 있다. 선택적인 연출이 잘못되어도 유효한 대사 전체를 버리지 않는다. 서술·행동·속마음에는 연출을 저장하지 않는다. 메시지의 기존 JSON 블록으로 전달·저장하므로 테이블 변경은 없다. 화면과 본문 렌더러는 연출 정보를 표시하지 않는다.

## 앱 → 음성 요청

`POST /api/tts`는 로그인, 대화 소유자, 공개되지 않은 메시지 상태를 확인하고 저장된 대사만 사용한다. 클라이언트가 보내는 임의의 text/voice/delivery는 사용하지 않는다. 텍스트형으로 제작된 캐릭터도 음성 모드를 켤 수 있다.

- `{sessionId,messageId,plan:true}`: 합성 없이 `{segments:[{part,pauseAfterMs}]}` 반환.
- `{sessionId,messageId,part:0}`: 해당 캐릭터의 지정된 대사와 연출만 `/speak`에 전달하고 오디오 반환.
- part가 없는 기존 요청: 기존 전체 대사 반환 계약 유지. 새 클라이언트는 항상 대사별 part를 요청한다.

`spokenSegments`는 서술·속마음·NPC와 다른 화자의 대사를 제외한다. 기존 연출 없는 메시지는 기본값을 사용하며 직전 서술·행동의 속삭임 단서만 해당 대사의 호환 신호로 쓴다. 전체 읽기 길이는 기존처럼1,200자로 제한한다.

2026-10-26 변경: 프런트는 확정·저장된 캐릭터 대사 최대 3개를 보여주고 사용자가 선택한 한 대사만 생성·재생한다. 자동 생성하지 않는다. 과거 순차 재생 함수는 호환용으로 남아 있다. 음성 모드는 방별로 저장되는 명시적 선택이며 처음에는 꺼져 있다. 끄거나 방을 떠나면 요청·대기·재생을 취소한다. 실패 시 준비/실패 상태와 수동 다시 듣기를 제공하며 다른 브라우저 목소리로 대체하지 않는다. 자동 유료 재시도는 없다.

## `/speak` → 실제 모델

`packages/providers/src/tts.ts`는 `MIRO_TTS_URL/speak`에 text/voice/language/style/delivery를 보낸다. `MIRO_TTS_API_KEY`는 서버에서만 사용한다.

`tooling/voice/drama3_fullft/miro_gateway.py`는 별도의 비공개 CPU 어댑터다. 서버 소유 registry에서 앱 voice ID를 Fish reference_id로 바꾸고, `miro_contract.py`가 허용된 연출 값을 모델의 자연어 연기 태그로 변환한다. Fish의 `/v1/tts`에는 JSON으로 전달한다. pace/intensity는 연기 지시이며 실제 수치 속도·dB 보장이 아니다. 대사 사이 쉼은 브라우저에서 실제 적용한다.

GPU 서버는 기존23 또는 후속 학습에서 내보낸 하나의 BF16 모델과 코덱을 사용한다. 두 목소리는 참조ID만 다르다. `serve_native_api.py`는 미리듣기에 쓰인 네이티브 가중치 로더 라우팅을 API 초기화에도 유지하고, 단일 프로세스/BF16로 설정한다. 실제 GPU API 기동은 이번에 실행하지 않았다.

필요 설정 예시는 `tooling/voice/drama3_fullft/serving.env.example`에 있다. registry는 운영자가 등록한 실제 참조ID로 채워야 한다. 현재 URL이나 키를 변경하거나 목소리를 등록하지 않았다. 기존 GSV 서버는 추가 연출 필드를 해석하지 않으므로, 새 연출을 쓰려면 이 어댑터와 Miro 모델 서버를 연결해야 한다.

## 검증과 한계

대화 엔진과 음성 경로 TypeScript279개 테스트, 가짜 native 서버를 사용하는 실제 로컬 HTTP Python2개 테스트, 320px/390px 브라우저 UI검사가 통과했다. 루트 및 웹 타입 검사도 수행했다. 모든 음성 응답은 로컬 mock/무음이고 외부 유료 합성은 없다. 모델의 실제 연기 성능·남성 음색·iPhone 실기기는 검증하지 않았다.

## 영속 작업 큐 — 10/24 후속 구현

`MIRO_TTS_QUEUE_ENABLED=1`이면 `POST /api/tts`는 DB 작업 ID와202를 반환한다. 클라이언트는 `/api/tts/jobs/:id`를 조회하고, 워커가 저장한 오디오를200으로 받는다. 웹 요청이 GPU 대기를 맡지 않는다. flag 기본값은0이며 기존 동기 경로를 유지한다. 이번에 운영 설정을 바꾸거나 마이그레이션을 적용하지 않았다.

- 캐시 키에는 소유자·방·메시지·대사 번호·전체 연출·언어·목소리·모델/참조 버전이 포함된다. 같은 요청은 동일 작업을 반환하며, 완료 오디오는24시간 재사용한다. 다른 사용자와 공유하지 않는다.
- 생성 전후와 결과 조회 때 현재 소유권·공개 상태·대사·참조를 다시 검증한다. 숨김/삭제/수정된 원문은 기존 캐시도 반환하지 않는다.
- 전역 DB 잠금으로 중복 제출·예산 예약·작업 할당 경합을 막는다. 전체 동시 합성1개, 대기/실행은 사용자2개·전체8개, 오디오4MiB/건·전체 캐시64MiB로 제한한다. 소규모 베타 설정이다.
- 생성 비용은 설정한 보수적 최대 비용을 요청 시 예약한다. 사용자/전체 최근24시간 한도를 넘으면 거절한다. 실제 클라우드 청구 연동이나 GPU 유휴 요금의 하드 제한은 아니다. 실측한 최대 비용 및 클라우드 자체 지출 제한을 확인하기 전 운영 활성화를 하지 않는다.
- 취소는 아직 전송되지 않은 작업만 제거한다. 실행 중 작업의 계산 중단을 보장하지 않는다. 워커 종료/시간 초과/응답 유실은 `uncertain`으로 격리하고 전체 큐의 신규 생성을 멈춘다. 자동 유료 재시도는 없다.
- 결과가 불명확한 작업은 운영자가 실제 GPU 계산 종료를 확인한 뒤에만 `--acknowledge-stopped UUID`로 해제한다. 이 명령은 기존 작업을 재실행하지 않는다. 기존 실패 건도 자동으로 재제출하지 않는다.

마이그레이션은 `packages/db/migrations/20261024135239_speech_synthesis_queue.sql`이다. 작업/독립 사용량 테이블은 RLS를 켜고 Data API 접근을 철회해 서버에서만 사용한다. 오디오는 임시 DB 캐시로 저장하며 장기 보관/대규모 오브젝트 스토리지 대체물이 아니다. 별도의 사용량 원장은 대화/계정 삭제에도 지출과 실행 잠금을 유지한다. 원장에는 텍스트·음성·직접 사용자 ID 대신 해시 키를 저장하며, 완료/미전송 기록은24시간 후 다음 요청 때 정리한다. 미확인 실행 기록은 운영자 확인 전까지 보존한다.

별도 서버 프로세스는 `pnpm speech:worker`로 실행한다. 웹과 같은 DB·모델/참조 버전·예약 한도 및 `MIRO_TTS_URL`을 설정해야 한다. 필수 정책 값 누락 시 실행을 거절한다. 워커에만 `MIRO_SPEECH_ALLOW_PROVIDER=1`이 필요하다. 설정 예시는 루트 `.env.example`에 있으며, 예시에 금액을 임의로 채우지 않았다. 웹을 활성화하기 전에 워커 가용성을 운영에서 확인해야 한다. 학습용 `voice:worker`와 다른 프로세스이며 학습을 시작하지 않는다.

추가 검증: 독립 로컬 Postgres에 전체 마이그레이션을 적용하고 실제 DB/HTTP 계약 테스트29개를 통과했다. 동시12개 요청의 단일 생성, 병렬 작업 할당, 캐시 재사용, 권한 변경, 중간 종료 격리, 비용 예약 경합과 취소를 포함한다. 합성 응답은 로컬 무음 fixture이며 실제 모델의 음질을 검증한 것은 아니다.

실제 Next 앱 브라우저 검사도 신규 가입·페르소나 설정·채팅 생성/저장·202 작업 접수·별도 워커 처리·결과 조회·실제 오디오 `ended` 이벤트·캐시 재조회·채팅 모드 복귀까지 통과했다. 페이지 JavaScript 오류는0개다. 모든 생성은 로컬 mock/무음이며, 결과는 `output/speech-queue-20261024/FULL_APP_CHECKS.json`에 보관했다. 검사 후 전용 앱/워커/가짜 합성 서버를 종료하고 자동 생성된 Next 캐시를 정리했다.

## 10/26 음성 분량과 상황 이미지

구체적인 최신 동작·검증·운영 순서는 `VOICE_CHARACTER_CHAT_RELEASE_PLAN.md`를 따른다. 신규 음성 초 원장 마이그레이션은 `20261026094906_speech_credit_accounts.sql`이며 운영에는 미적용이다. 크레딧 모드는 영속 큐가 필수이고, quote 요청은 생성하지 않으며, 실제 요청에는 명시적 confirmed가 필요하다. 무료 캐시 재생은 reuseOnly로 보호해 만료 중 자동 유료 생성하지 않는다.

`maxAudioSeconds`는 앱 서버가 정한 10/20초를 네이티브 토큰 상한으로 전달한다. 보통/길게는 모델 품질 차등이 아니다. 반환 WAV를 서버에서 검사하고 1초 단위 올림해 정산하지만 대사 내용 완주까지 검증하는 기능은 아니다. 최신13 모델 실제 음성 검증과 GPU 원가는 Modal 정지 때문에 아직 대기다.
