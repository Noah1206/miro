# 문자 경험 — 전송, 읽기, 답장 분리

2026-10-14 로컬 구현. 운영 DB 적용·배포와 실제 모델 문체 검증은 수행하지 않았다.

문자는 장면 채팅의 한 턴이 아니다. `/api/messages`는 사용자의 문자를 저장하고 끝낸다. 입력창은 즉시 비워져 계속 작성·전송할 수 있고, 캐릭터의 답변을 기다리는 회전 아이콘과 가짜 ‘입력 중’ 표시는 없다. 전송 실패는 해당 말풍선에서 같은 요청 ID로 재시도한다. 구형 문자 진입점도 같은 수신 경로로 연결된다.

`messenger_inbox`가 문자마다 읽음과 처리 상태를 저장한다. 전송 직후에는 읽지 않음이며, 화면을 새로 열어도 읽음 상태가 유지된다. 기존 문자에는 확인할 수 없는 읽음 시각을 소급해서 붙이지 않는다. 카톡 테마는 읽지 않은 문자 옆에 1을 표시하고, DM 테마는 실제 읽은 뒤 ‘읽음’을 표시한다.

전송 뒤 첫 검토에서 캐릭터는 ‘지금 읽기’, ‘나중에 다시 판단하기’, ‘읽지 않고 두기’를 선택한다. 검토 시각은 읽음을 강제하는 타이머가 아니다. 수면·통신 불가 상태에서는 미열람을 유지하고, 바쁜 상태에서는 현재 상황을 알려 캐릭터가 짧게 확인할지 판단할 수 있다. 열람 판단은 기존 자율성 코어와 같은 작성 설정·성격 규칙, 관계, 캐릭터 상태와 감정, 목표, 기존에 관측한 기억·사건을 사용한다.

미열람 본문·길이·미리보기·주제·긴급도는 판단기에 전달하지 않는다. 발신자와 도착 시각·메시지 식별자만 전달한다. 선택은 캐릭터 규칙과 알려진 근거 ID를 인용해야 한다. 모델 실패나 근거 검증 실패는 읽음으로 처리하지 않는다. 선택을 생성하는 동안 새 메시지, 관계·세계·감정 상태 또는 캐릭터 설정이 바뀌면 오래된 선택은 저장하지 않고 다시 판단한다.

‘나중에’는 캐릭터가 선택한 1분~24시간 뒤의 재검토이며 그때도 다시 미룰 수 있다. ‘읽지 않고 두기’는 미열람으로 남는다. 이후 재검토 시점이 와도 판단 맥락이 같으면 모델 호출 없이 계속 미열람을 유지한다. 새 연락, 관계·감정·세계 상태의 변경, 생활 일정의 변화나 새로운 관측 경험이 생기면 다시 판단한다. 앱을 닫거나 서버를 재시작해도 선택과 읽음 상태를 DB에서 이어간다.

읽은 뒤 답장 검토까지 별도의 시간(최소 20초)을 둔다. 화면이 열려 있으면 5초 간격의 동기화가 작업을 깨우고, 앱을 닫으면 서버 크론이 이어간다. 새 1분 크론은 기존 ops 설정과 pg_cron/pg_net이 준비된 환경에만 등록된다. 정해진 지연은 정확한 답장 시각을 보장하지 않는다.

읽은 문자는 기존 캐릭터 자율성 코어에 전달한다. 성격, 관계, 공유한 기억과 실제 내용으로 답장·보류·답하지 않기를 선택한다. 답하지 않는 선택은 읽음 상태로 남고 같은 문자 때문에 매번 판단을 재실행하지 않는다. 나중의 연락 약속을 만든 경우에는 기존 목표 실행 경로가 이어간다. 모델/자율성 준비 실패는 읽은 문자를 버리지 않고 재시도한다.

장면과 문자는 같은 관계·기억·인물 설정을 공유한다. 아직 읽지 않은 문자는 장면 맥락과 기억 요약, 자율성 근거에서 제외한다. 읽은 뒤 기억 추출 작업을 등록하므로 문자에서 알려준 사실도 장기 기억으로 이어진다. 문자 전송은 장면 생성 중에도 가능하며, 상태가 바뀐 동안 생성된 오래된 답장은 다시 판단한다. 읽음 처리와 모델 실행을 분리해 긴 모델 호출이 입력을 잠그지 않는다.

답장 저장, 문자 처리 완료, 캐릭터 판단·관계 변경과 푸시 작업은 같은 트랜잭션으로 확정한다. 작업 임대와 요청 ID로 동시 검토·재전송을 제한한다. 답장 작업은 별도 선연락 의도를 덮어쓰지 않는다. 사용자의 선연락 중단 요청은 계속 적용하며, 사용자가 새로 보낸 문자에 대한 응답과 구분한다. 기기 푸시 허용 설정은 그대로 적용한다.

배포 전에 `packages/db/migrations/20261014135430_messenger_inbox.sql`과 `20261014142038_messenger_attention_decisions.sql`을 순서대로 적용한다. 새 테이블은 서버 전용이고 RLS를 켜며 앱의 직접 접근 권한을 주지 않는다. 운영 코드가 이 테이블을 읽기 때문에 DB 적용이 코드 배포보다 먼저여야 한다.

검증은 격리된 로컬 테스트 DB와 기록된 모델 응답으로 수행한다. 연속 전송·멱등 재전송, 소유권, 장면 생성 중 전송, 수면 중 미열람, 열람/응답 분리, 읽은 뒤 답하지 않는 선택, 중복 답장 방지와 기존 약속 보존을 확인한다. 모바일 UI에서는 전송 중에도 작성·추가 전송이 가능하고, 읽음 기록이 바뀐 뒤에만 화면이 갱신되며 새로고침 후 유지되는지 확인한다. 실제 인물별 반응 품질과 운영 크론·기기 전달은 별도 확인이 필요하다.

## 최종 검증 기록

- 루트 타입 검사 통과.
- 메시지·관계·기억 관련 검사 75개 통과, 장면 맥락 검사도 전체 실행에서 통과.
- 모바일 화면 회귀 검사 1개 통과: 전송 요청을 멈춰 둔 동안 다음 문자를 입력·전송, 도착 순서 뒤바뀜 방지, 실제 읽음 기록 반영과 새로고침 유지.
- 전체 1,054개 중 1,022개 통과, 1개 건너뜀, 31개 실패. 같은 31개 실패가 변경 전 HEAD의 격리된 소스에서도 재현됨(기존 요금·결제·응답 길이 검사 등). 전체 성공으로 보고하지 않는다.

## 열람 선택 추가 검증

기록된 모델 선택으로 즉시 열람, 반복 보류, 맥락이 그대로일 때 미열람 유지·모델 호출 생략, 관계 변경 및 새 연락에 따른 재판단, 미열람 본문 비노출, 현재 감정 전달, 판단 중 새 메시지 도착 시 오래된 선택 취소, 모델 실패 시 미열람 유지와 임대 반환을 검사한다. 실제 모델의 대표 상황 검증은 [검증 기록](verification/2026-10-14-messenger-attention-live.md)을 따른다.

추가 열람 선택 구현 후 전체 검사에서는 1,060개 중 1,028개 통과·1개 건너뜀·기존 31개 실패를 확인했다. 이후 자율성 중단 중 생성된 읽음 선택의 저장 차단 검사도 추가했으며, 최종 관련 검사 82개와 타입 검사를 다시 확인한다.

실제 운영 모델 28건의 수정 후 열람 선택 검증과 관련 검사 82개를 통과했다. 배포는 준비된 개정판을 대상으로 하며 실제 설정 컴파일 및 장기 관계 품질은 별도 검증 범위다.
