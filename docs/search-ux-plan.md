# 검색 UX·로직 실행 계획

## 목표와 현재 상태

홈에서 보이는 공식 또는 공개 `chat`·`reality` 캐릭터를 검색에서 찾고, 검색 진입→한글 입력→결과 확인→상세 왕복이 빠르고 일관되게 동작하도록 한다. 기존 Next.js/Postgres, 12개 단위 keyset 페이지네이션과 접근권한 규칙은 유지한다. 아래 표는 계획을 세울 때의 구현 상태를 기록하며, 실제 완료 범위는 다음 절에서 구분한다. 운영 DB나 플래그는 변경하지 않는다.

### 실행 상태 (2026-09-23)

- **구현:** `chat`·`reality` 통합 검색과 기존 소유자 비공개/공식/공개 가드, 빈 검색조건 조회 생략, 제출형 입력·작은 검색 버튼·URL 동기화·한글 조합 방지, 헤더 X 제거, 별도 태그 조건과 클릭/`#` 입력 경로. 태그는 `tag` URL 조건으로 장르 조각·관계 키워드를 정확히 비교한다.
- **구현:** 대화형/리얼리티 유형 필터와 보이는 ‘최신순’ 문구를 제거했다. 기존 `type=chat`/`type=reality` URL은 유형 제한 없이 canonical URL로 이동한다. 만들기·편집의 ‘장르’ 복수 선택은 공통 16개 선택지와 직접 입력을 사용해 `worlds.genre`에 최대 5개를 ` · `로 저장한다. 검색의 반복 `genre` URL 값은 최대 5개까지 정규화·중복 제거·정렬하며, 여러 장르 사이 OR, `q`/`tag`와 AND, 모든 세계의 장르 조각에서만 정확히 일치시킨다. 직접 입력한 장르는 기존 `#`태그 검색과 직접 `genre` URL로 찾을 수 있다. 선택 없는 검색은 기존과 같고 장르만 선택해도 검색한다.
- **구현:** 12+1 keyset과 검색어/태그/장르 집합 조건 fingerprint, 결과 ID 중복 제거, 더 보기 fetch 취소·늦은 응답 무시, 최초/추가 페이지 실패의 재시도와 빈 결과·진행 안내. 검색 페이지의 현재 사용자 조회와 API의 `private, no-store`는 유지한다. 결과 정렬은 문구 제거와 무관하게 생성 시각·ID 내림차순이다.
- **검증:** guarded `miro_test`의 검색·홈/미로 통합 테스트 14개와 타입 검사 통과. localhost 브라우저에서 홈 1회 진입, 강태준 결과·상세 왕복, 유형 필터, 태그 클릭·단독 입력을 확인했다. 운영 인덱스 플래그나 데이터는 변경하지 않았다.
- **추가 검증:** 격리된 localhost 앱과 guarded `miro_test`의 17건 fixture로 12→17개 더 보기 후 두 번째 페이지 카드의 상세·뒤로가기를 확인했다. 17개와 스크롤 Y=3153.636이 복원되며 입력에 다시 초점이 가지 않았다. 복원은 카드 데이터가 아닌 조회조건·사용자 ID·페이지 수·스크롤 위치만 세션 저장소에 5분 보관하고 서버에서 재조회한다. 별도 지연 응답 모의 브라우저 검증에서 추가 페이지 중 중복 클릭 방지, 추가/최초 실패 재시도, A→B→A의 오래된 A 응답 무시를 확인했다. 실제 `SearchHeader`에서 A 제출의 RSC 응답을 지연하고 B로 편집한 뒤 A 완료 시에도 B 초안이 유지되며, 이어 뒤로/앞으로 이동하면 확정된 URL의 `q`로 입력이 동기화됨을 확인했다. 복원 키·만료·페이지 상한 단위 테스트와 타입 검사도 통과했다.
- **장르 검증:** guarded `miro_test`의 검색/만들기 파서/복원 테스트 9개를 통과했다. 만들기 파서의 두 장르 저장→각 장르 검색, 서로 다른 세계 장르, 관계 키워드만 같은 항목 배제, 공개/소유자 비공개 권한, 12개 경계와 중복 제거, 장르 순서·중복 정규화 및 다른 집합 커서 거부를 검증했다. localhost 브라우저에서는 기존 `type=chat` URL 정리, 강태준의 드라마·느와르 복수 선택·해제, 장르만으로 결과 조회, 뒤로/앞으로 선택 복원, 필터 변경 중 미제출 입력 초안 보존과 만들기 성격·장르 탭의 장르 칩 복수 선택 표시를 확인했다. 레거시 `type=chat`을 붙인 검색 API도 리얼리티 결과를 반환하고 `private, no-store`를 유지했다. 운영 데이터·플래그는 바꾸지 않았다.
- **남은 확인:** 실기기 IME/모바일 키보드, 인증 전환의 실제 브라우저 재현, 변경 전후 지연·요청 수 측정은 완료로 주장하지 않는다. 관련성순·최근 검색·자동완성·초성/오타·개인화는 후속 제품 결정이다.

## 1차: 정확성과 기본 UX

1. **대상·권한:** `searchPage`가 `chat`·`reality`를 함께 찾도록 `apps/web/lib/home.ts`의 조회 범위와 가시성 조건을 분리한다. 최초 페이지와 더 보기 API에서 공식/공개/본인 비공개만 허용하고 초안·삭제를 제외한다. 비공개 카드가 공용 캐시에 섞이지 않도록 API의 `private, no-store`를 유지한다. 공개 강태준과 `chat` 샘플이 모두 검색되며 카드에서 각 상세·시작 흐름으로 올바르게 이동해야 한다. 홈과 검색의 본인 비공개 노출 차이는 의도적으로 유지한다.
2. **입력·탐색:** 검색창 상시 표시와 최초 진입 포커스를 유지하되, 상세에서 뒤로 돌아올 때 매번 키보드가 열려 결과를 가리지 않도록 복원 진입을 구분한다. 검색어 지우기를 유지하고, 검색 입력의 접근성 이름 및 작은 제출 버튼의 명확한 이름을 제공한다. 모바일 검색키는 `enterKeyHint="search"`를 유지한다. placeholder는 실제 지원하는 이름·장르·키워드로 바꾸고, 의미 기반으로 ‘분위기’를 이해한다고 암시하지 않는다. 상세 왕복 후 확정된 `q`, 결과, 가능한 스크롤 위치를 복원한다.
3. **제출·URL:** Enter/모바일 검색키/작은 제출 버튼만 검색을 실행한다. 한글 조합 확정 Enter는 검색으로 취급하지 않는다. 편집 중 DB 요청은 0회; 공백만 있는 제출과 동일 조건의 반복 요청을 막는다. 편집 중 값과 URL의 확정 `q`를 분리하고, 뒤로/앞으로/직접 URL 진입 시 입력·결과를 동기화한다. 명시적 새 검색은 `push`, 내용 지우기·조건 초기화는 `replace`로 불필요한 이력을 줄인다. 쿼리 변경 시 리스트와 커서를 초기화한다.
4. **상태:** 빈 `q`는 대규모 기본 목록을 조회하지 않고 ‘이름이나 키워드로 캐릭터를 찾아보세요’를 표시한다. 검색 중 입력·헤더를 유지하며 결과 영역에 진행 상태를 보인다. 새 검색을 기다리는 동안 이전 결과가 남는다면 이전 조건의 결과임을 명확히 구분한다. 0건은 검색어 수정 안내, 최초 실패는 독립된 오류와 같은 조건 재시도, 추가 페이지 실패는 기존 결과와 하단 재시도를 제공한다. 과거 route loading 경계가 지연을 만들었던 성능 검증을 존중해 전체 화면을 막는 새 `loading.tsx`를 기본 해법으로 삼지 않는다.
5. **쿼리·커서:** 서버 40자/trim/소문자·공백 정규화를 UI·일반 SQL·indexed 경로에서 일치시키고 한글 완성형 및 문자 그대로의 `%`·`_`를 검증한다. 요청 조건 변경 시 진행 중인 더 보기 fetch를 가능하면 취소하고 늦은 응답은 무시한다. 취소가 이미 시작된 DB 작업까지 반드시 중단한다는 보장은 하지 않는다. 기존 12+1 keyset, ID 중복 제거, 대표 이미지 1장 반환, 정확한 총건수 `COUNT` 생략을 유지한다. 커서에 정규화 검색어와 태그·장르 집합 등 조회조건의 fingerprint를 담아 다른 조건의 커서를 거부한다. 커서는 권한 증명이 아니며 모든 페이지에서 사용자 기준 가시성을 다시 검사한다.

수정 범위는 주로 `apps/web/lib/home.ts`, `apps/web/app/(main)/home/search/{page,search,grid}.tsx`, `apps/web/app/api/home/search/cards/route.ts` 및 인접 통합 테스트로 제한한다. 빈 검색조건의 서버 조회 생략은 페이지와 더 보기 API에서 동일하게 적용한다.

## 2차: 기본 동작 검증 후 작은 확장

- 유형 필터는 사용자 결정에 따라 제거했고 검색은 언제나 `chat`·`reality` 전체를 포함한다. 장르 복수 선택이 현재의 검색 필터다.
- `#`태그 클릭·입력을 도입할 때는 장르/키워드 태그 검색과 일반 문자 그대로의 검색을 구분한다. 현재는 여러 세계 중 하나의 장르가 매치되어도 카드에는 첫 세계의 장르만 표시될 수 있다(`apps/web/lib/home.ts:22`, `apps/web/lib/home.ts:60-64`). ‘매칭된 태그’ 표시 여부를 함께 결정한다.
- 정렬은 최신순을 유지하되 요청에 따라 라벨은 표시하지 않는다. 관련성순은 이름 완전일치·접두·장르/키워드 우선순위와 안정적인 커서 정렬을 설계·측정한 뒤 검토한다. 최근 검색은 필요성이 확인되면 기기 저장 소수 항목과 개별/전체 삭제부터 검토한다. 서버 저장, 개인화, 실시간 인기어, 자동완성, 초성·오타 검색은 이번 필수 범위 밖이다.

## 성능·롤아웃·완료 기준

제출형 검색에서는 debounce, 새 검색엔진, 전역 공유 캐시를 도입하지 않는다. indexed-discovery는 기존 `docs/indexed-discovery-rollout.md`의 backfill·권한·검증·점진 활성화 순서로 **별도 배포**한다. 나중에 자동검색을 선택할 때만 debounce·IME 처리·오래된 응답 방지를 설계한다. React의 `useDeferredValue`만으로 네트워크 요청 수가 줄지는 않는다. 서버 실행 시간과 사용자가 체감하는 결과 대기 시간을 분리하고, 동일 데이터·워밍 조건에서 변경 전후 p50/p95·오류율·요청 수를 비교한다. 짧은 로컬 부하 결과를 실제 동시사용자 수용량으로 해석하지 않으며 측정 전 절대 p95 목표도 약속하지 않는다.

검증은 **guarded localhost 테스트 DB**의 fixture와 브라우저 조작에 한정하며 운영 데이터·업로드 원본을 보존한다. 익명/소유자/타인 각각에서 공개 `chat`·`reality`·공식, 본인/타인 비공개, 초안, 삭제를 검증해 권한 회귀를 0으로 만든다. 한글 조합 Enter, 공백/대소문자/문자 그대로의 `%_`/40자/빈 `q`, 뒤로·앞으로·직접 URL, 빠른 두 검색의 늦은 응답, 쿼리-커서 불일치, 12개 초과 페이지 중복, 최초/0건/실패/재시도, 첫 포커스와 상세 왕복을 확인한다. 성공 기준은 검색 진입 1회, 타이핑 중 서버 검색 요청 0회, 느린 네트워크에서도 입력 유지와 진행 안내, 검증된 공개 강태준 조회, 비공개 누출 0건이다.

참고: [Next.js 검색·페이지네이션 가이드](https://nextjs.org/learn/dashboard-app/adding-search-and-pagination)는 URL과 입력 상태 동기화·페이지 초기화 및 **자동검색을 선택한 경우** debounce를 설명한다. [React `useDeferredValue`](https://react.dev/reference/react/useDeferredValue)는 렌더링 지연과 네트워크 요청 절감이 별개임을 명시한다. 이 참고 패턴은 위의 제품 제안이며, 현재 구현 완료를 뜻하지 않는다.
